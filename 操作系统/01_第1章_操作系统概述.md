## 知识点详解

### 一、1.1 操作系统基本概念

**定义**：操作系统（OS）控制和管理整个计算机系统的**硬件资源和软件资源**，合理组织调度计算机的工作与资源分配，为用户和其他软件提供方便的接口与环境（后半句为教材补充）。

- 硬件资源：CPU、内存、I/O 设备；
- 软件资源：程序、文件（视频/文档/音频文件都算）。

**四大资源管理功能与章节对应**（学完后继章节再回看，第一轮不必深究）：

| 管理功能 | 对象 | 对应章节 |
|---|---|---|
| 处理机管理 | 进程/线程、CPU 调度 | 第 2 章 |
| 存储器管理 | 内存分配、分页分段、虚拟内存 | 第 3 章 |
| 文件管理 | 文件、目录、磁盘空间 | 第 4 章 |
| 设备管理 | I/O 设备、磁盘调度 | 第 5 章 |

**用户接口三类**：

| 接口 | 别名 | 工作方式 | 交互性 |
|---|---|---|---|
| 联机命令接口 | 命令行接口 | 敲一条命令→立即解释执行→给反馈，逐条进行 | 有（实时交互） |
| 脱机命令接口 | 批处理接口 | 一堆命令写成脚本一次性全部执行完，中途不干预 | 无 |
| 图形用户接口 | GUI | 鼠标点图标、双击启动软件 | 有，使用门槛最低 |

**程序接口 = 系统调用**。应用程序想使用操作系统的服务，必须通过系统调用；系统调用可理解为"操作系统把代码写好、把功能封装成函数，编程时直接调用"。

> 关键细节（考过）：`printf` **不是**系统调用，它是**标准库函数**；库函数是对系统调用的**封装**，`printf` 内部最终通过 `write` 这个系统调用完成输出。即"用户程序 → 库函数 → 系统调用 → 内核"。

#### 四大特征（并发 / 共享 / 虚拟 / 异步）

**（1）并发（Concurrency）**

定义：两个或多个事件在**同一时间间隔内**发生；本质是**在极短时间间隔内交替执行**。

老师举的数字例子：4 个程序 P1、P2、P3、P4，只有 1 个 CPU，让每个程序各执行 **1 纳秒（1 ns = 10⁻⁹ s）**，然后切换。因为切换太快，人根本感知不到 CPU 在四个程序间来回跳，感觉上就像四个程序同时在跑——这就是并发。

> 口误订正：字幕原话"一纳秒相当于十的九次方秒"，应为 **10⁻⁹ 秒**（原文存疑，按物理量为 10⁻⁹ s）。

**并发 ≠ 并行**：

| | 并发 | 并行 |
|---|---|---|
| 时间 | 同一时间**间隔**内 | 同一**时刻** |
| 微观 | 交替执行（单 CPU 轮流） | 同时执行 |
| 硬件条件 | 1 个 CPU 即可 | 需多处理机/多核 |
| 例子 | 1 个 CPU 上 P1、P2 各跑 1 ns 交替 | CPU1 跑 P1、CPU2 跑 P2；CPU 跑 P1 的同时打印机打印 P2 的内容；键盘与打印机同时工作 |

- CPU 与 I/O 设备**可以并行**（不同硬件，同一时刻各干各的）；
- 多个 I/O 设备之间**也可以并行**（打印机 + 键盘）；
- **同一个硬件**被多个程序使用，只能**并发**（如只有一台打印机，P1、P2 必须错开用）。

**反例（没有并发会怎样）**：若系统只允许一道程序从头跑到尾，则程序一旦发起打印（需 5～10 分钟且几乎不占 CPU），CPU 只能干等，利用率极低；多个程序也无法"看起来同时运行"，用户开第二个软件就得等第一个彻底结束。

**（2）共享（Sharing）**

定义：系统中的资源可供内存中多个并发执行的进程共同使用。两种方式：

| 方式 | 含义 | 典型资源 | 反例（破坏后的后果） |
|---|---|---|---|
| 互斥共享 | 一段时间内只允许一个进程访问；A 未释放前 B 必须等 | 打印机、共享全局变量（**临界资源**） | 两个进程同抢一台打印机，若允许同时写，A、B 两个文档的字会**交错打在同一张纸上**，内容全乱 |
| 同时访问 | 宏观上"同时"，微观上仍是**交替**访问 | 磁盘、可重入代码 | 若要求磁盘也整段独占，P1 读 1000 字节期间 P2 完全不能动，响应变慢、利用率低 |

同时访问的数字例子：P1、P2 各要读磁盘 1000 字节，可让 P1 读 1 字节 → P2 读 1 字节 → P1 再读 1 字节……交替进行，各 1000 次完成。但打印机不行：不能在同一张纸上"你打 1 字节我打 1 字节"，必须等 P1 的 1000 字节全部打完。

**反例（没有共享会怎样）**：资源若只能独占，多道程序根本无法共存——每个进程都要独占整台打印机、整块磁盘、全部内存，并发失去意义，资源利用率退化为单道。

**（3）虚拟（Virtual）**

定义：把一个物理实体变成若干个逻辑对应物。

| 类型 | 做法 | 数字例子 | 反例（没有它会怎样） |
|---|---|---|---|
| 虚拟存储器 | 只把当前用到的部分调入内存 | 内存仅 16 GB，程序共 32 GB，每次真正运行的代码+数据只有 4 GB，只需把 4 GB 放入内存即可运行，用户感觉有 32 GB | 32 GB 的程序在 16 GB 机器上**根本装不下、跑不起来**，必须加内存条 |
| 处理器分时复用 | 时间片轮转 | 4 个程序轮流各用 CPU 1 ns，用户感觉像有 4 个 CPU | 4 个程序抢 1 个 CPU，用户会觉得每个程序都卡，只能买 4 核 |

要点：**物理实体不变**（16 GB 始终是 16 GB），变的只是"用户感觉到的逻辑容量"。

**（4）异步（Asynchrony）**

定义：进程的执行**并非连续**，而是**以不可预知的速度**向前推进，即"走走停停"。

数字例子：P1 有步骤 1→2→3，P2 有步骤 4→5→6。单道时各自连贯执行；并发后可能出现 1 → 4 → 5 → 2 → 3 → 6，也可能 1 → 2 → 4 → 5 → 3 → 6，顺序不确定。

**反例（没有异步会怎样）**：如果执行永远连续、可预知，就不存在"跑到一半被切换"，也就没有"结果不可再现"的问题，2.3 节的同步互斥机制就完全没必要。反过来，**正因为异步**，两个程序对共享变量的访问顺序才不确定，才必须用同步机制把顺序"钉死"（如强制 P1 的 1、2 执行完才允许 P2 执行 4）。

**四特征关系**：并发和共享是**两个最基本特征**，二者互为存在条件（没有并发就无需共享，没有共享并发也无法推进）；没有并发和共享，就谈不上虚拟和异步。

### 二、1.2 操作系统发展历程

| 阶段 | 核心做法 | 缺点 / 特点 |
|---|---|---|
| 手工操作阶段 | 无操作系统，程序的装入、执行、结果输出全靠人工 | 人工输入极慢，CPU **长时间空闲等待人工完成 I/O** |
| 脱机 I/O 阶段 | 增设**外围机**专门负责 I/O 准备，完成后再交给 CPU | 缓解 CPU 等 I/O，仍需人工干预 |
| 单道批处理 | 内存中**只能放一道**程序，执行完一道才装入下一道 | 无交互；CPU 在 I/O 期间仍空闲 |
| 多道批处理 | 内存中放多道程序，某道因 I/O 暂停就**立即切换**到另一道（依赖**中断技术**） | 无交互能力、**响应时间长**、系统开销大 |
| 分时系统 | 处理机时间切成很短的**时间片**，轮流分给各程序 | 有交互性、独立性、及时性 |
| 实时系统 | 在**严格时间限制**内完成关键任务，按**任务紧迫性**调度（优先级） | 硬实时 / 软实时 |

**多道批处理为什么能提高利用率**（老师的具体流程）：

P1 先用 CPU 执行一段 → 进入 I/O（如打印，把数据送到 I/O 接口，此阶段几乎不需要 CPU）→ CPU 空出，立刻让 P2 使用 → P1 的 I/O 完成后再发中断回来继续。这就是"当某程序因 I/O 请求暂停，CPU 立即切换到另一程序"。

**多道批处理为什么"没有交互能力"**：若 P1 长时间占用 CPU，P2（比如笔记软件）即使有新输入，也得等 P1 让出 CPU 才能响应，延迟太久就不叫交互。

**分时系统为什么"有交互能力"**：时间片很短，数字例子——P1、P2、P3 各执行 **1 秒**，1 秒到不管有没有算完都强制让出 CPU。于是 P3 的新输入最多等 2 秒就能被处理，用户感觉"随敲随出"。

- **独立性**：各用户相互隔离，每个用户都感觉自己**独占**整个系统；
- **及时性**：用户请求能在较短时间内获得响应。

**实时系统与分时的区别**：分时"过于公平、时间过于均匀"，紧急任务也必须排队等轮转；实时按**紧迫性**（优先级）调度，紧急任务优先拿到 CPU。

其余名词（网络 OS、分布式 OS、微机 OS 如 Windows/macOS/Linux、服务器版 UNIX/Linux/Windows Server）只需认得术语，不深究。

### 三、1.3 操作系统的运行环境（全章核心）

#### 3.1 内核的支撑功能

| 功能 | 说明 |
|---|---|
| 时钟管理 | 底层有专门**定时器**硬件，周期性发出**时钟中断**，据此计时、维护系统时间、实现时间片 |
| 中断机制 | 提高资源利用率：程序发起 I/O 后阻塞自己、让出 CPU；I/O 完成发中断再回来 |
| 原语 | 若干条指令组成的**原子**操作，执行过程不可被打断；运行在**内核态**；一般靠**关中断**实现 |
| 资源管理 | 进程管理、存储器管理、设备管理（后续章节） |

**时钟中断的具体数字例子（对应题单第 25 题）**：定时器每隔 **10 ms（0.01 s）** 发一次时钟中断。给 P1 分配时间片 **50 ms**，P1 已运行 **20 ms** 时发生时钟中断，转去执行时钟中断服务程序，它做三件事：

1. 修改系统时间变量（所以屏幕上的时间"每秒都在变"，其实是每 0.01 s 悄悄改一次，人察觉不到）；
2. 记录当前进程已占用 CPU 的时间：**20 ms**；
3. 修改时间片剩余：**50 − 20 = 30 ms**。

若剩余 30 ms > 0，返回 P1 继续；若时间片用完，则不再返回 P1，切换到其他进程。

**中断为什么能提高利用率**：P1 打印需 5～10 分钟且不需 CPU，此时把 P1 阻塞、CPU 去跑 P2；打印完成发 I/O 中断，再打断 P2 回到 P1 继续。

**原语的"原子性"**：P1 若只是普通 4 条指令，执行到第 2 条就可能被中断；把这 4 条整体定义为原语后，中途不允许打断，必须 4 条全执行完（靠关中断实现）。

#### 3.2 内核态与用户态

三组**一一对应**的概念，必须背成对：

| 程序 | 编译后成为 | 运行状态 |
|---|---|---|
| 用户程序 | 非特权指令 | 用户态 |
| 内核程序 | 特权指令 | 内核态 |

状态标志：由**硬件**的一个二进制位表示，存放在**程序状态字寄存器 PSW** 中：**0 = 内核态，1 = 用户态**。

| 指令类型 | 允许执行的态 | 典型指令 | 说明 |
|---|---|---|---|
| 特权指令 | **仅内核态** | 关中断/开中断、设置时钟、启动外部设备、**I/O 指令**（访问端口）、修改 PSW、设置中断屏蔽字、清内存、停机、**返回用户态指令** | 用户态执行会陷入异常/被拒绝 |
| 非特权指令 | **用户态和内核态都可执行** | 算术运算、逻辑运算（取反）、数据传送（取数/存数）、跳转、压栈、设置断点、**陷入指令 trap** | 内核态权限更高，普通指令当然也能执行 |

> 高频陷阱：教材原话"非特权指令**通常**在用户态执行"，不等于"只能"。真题第 30 题"内核态只能执行特权指令"是**错的**。

#### 3.3 用户态 ⇄ 内核态的转换途径

**唯一入口：中断或异常**（系统调用在机制上属于"自陷"，也是异常的一种，所以不必单列）。

| 途径 | 方向 | 触发方式 | 主动/被动 | 例子 |
|---|---|---|---|---|
| 外中断（中断） | 用户态 → 内核态 | 外部事件，与当前指令无关 | 被动、异步 | 时钟中断、I/O 完成中断、键盘/鼠标、打印机缺纸 |
| 内中断（异常） | 用户态 → 内核态 | 当前指令执行出错或主动陷入 | 被动（故障）/ 主动（自陷） | 缺页、除零、地址越界、**系统调用 trap** |
| 返回指令（特权） | 内核态 → 用户态 | 中断/异常处理完毕 | — | 中断返回、系统调用返回 |

**关键细节（反复考）**：

- **陷入指令 trap 在用户态执行**，执行完（由硬件把 PSW 模式位改为内核态）才进入内核态。所以"trap 是特权指令""trap 在内核态执行"都错。
- **把 CPU 模式从用户态改为内核态，是硬件完成的，不是操作系统完成的**（真题第 31 题）。
- **中断/异常的"发生"在用户态，"处理"在内核态**（真题第 16、17、33 题）。如缺页：用户态执行指令时发现缺页（发生），转内核态执行缺页处理程序（处理）。
- 被中断的程序一般在用户态，但**多重中断**时被中断的可能是内核态的中断处理程序；**中断处理程序一定在内核态**。

#### 3.4 中断与异常的分类

| 大类 | 别名 | 信号来源 | 子类 | 典型例子 | 返回位置 |
|---|---|---|---|---|---|
| **内中断** | **异常**（exception） | CPU **内部**，正在执行的指令引起 | **故障 fault** | 缺页、除零、地址越界、非法操作码、存储保护错 | 故障：返回**当前指令**重新执行（可修复）；不可修复则终止 |
| | | | **自陷 trap** | **系统调用**、条件转移、断点设置 | 返回**下一条**指令 |
| | | | **终止 abort** | 硬件故障：控制器出错、存储器校验错、电源掉电 | **不返回**，终止程序 |
| **外中断** | **中断**（interrupt） | CPU **外部** | **可屏蔽中断 INTR** | 打印机缺纸、I/O 完成、时钟中断 | 返回**下一条**指令 |
| | | | **不可屏蔽中断 NMI** | 电源掉电等紧急事件 | 返回下一条（若还能返回） |

两种交叉叫法（组成原理也讲，必须会对号）：

- **软件中断 = 故障 + 自陷**（由指令引起，软件可见）；
- **硬件中断 = 终止 + 外中断**（由硬件发出）。

**指定回答**：

- **缺页 → 内中断（异常）→ 故障 fault → 属软件中断**。它是在执行指令、按地址码访存时才发现"数据不在内存"，可修复（从外存调入后再执行本条指令），返回**当前指令**。
- **除零 → 内中断（异常）→ 故障 fault → 属软件中断**。执行到该指令才发现除数为 0，属**不可修复**的故障，通常终止程序，不返回。

**老师对返回位置的概括与细化**：老师原话"异常通常返回下一条，中断返回下一条；故障有时返回本条、有时程序直接停止"。准确对照见上表（教材补充细化：自陷返回下一条、故障返回本条、终止不返回）。

#### 3.5 中断处理过程（九个步骤）

| 阶段 | 步骤 | 由谁完成 |
|---|---|---|
| 中断隐指令 | ① 关中断 | **硬件** |
| | ② 保存断点（PC、PSW） | **硬件** |
| | ③ 引出中断服务程序（查中断向量表，取入口地址） | **硬件** |
| 中断服务程序 | ④ 保护现场（保存通用寄存器） | **操作系统** |
| | ⑤ 分析中断原因，转入对应处理 | 操作系统 |
| | ⑥ 执行具体中断处理 | 操作系统 |
| | ⑦ 恢复现场（恢复通用寄存器） | 操作系统 |
| | ⑧ 开中断（支持多重中断） | 操作系统 |
| | ⑨ 中断返回（恢复 PC、PSW） | 操作系统 |

记忆分界：**前 3 步硬件、第 4 步起是操作系统（中断服务程序）**。真题反复考"保存断点（PC）是硬件做的""保存通用寄存器是操作系统做的"。

**中断向量表**：本质是一个**数组**，下标 = 中断类型号，表项 = 该中断服务程序的**入口地址（中断向量）**。用数组才能"按类型号 O(1) 定位"。

#### 3.6 中断与子程序调用（函数调用）的区别

| 对比项 | 中断处理 | 子程序调用 |
|---|---|---|
| 关联性 | 与被中断程序**无固定关联**（随机发生） | 与调用者**有关联**，有主从关系 |
| 触发方式 | **随机**（指令出错或外部请求） | 程序中**主动**写出调用 |
| 运行态 | 中断处理程序**一定在内核态** | 与被调函数同态（用户态调用户态） |
| 保存 PC | **必须保存** | **必须保存** |
| 保存 PSW | **必须保存**（中断可能随时改标志位） | **一般不需要** |
| 保存通用寄存器 | **必须保存**（第 4 步） | **不一定**（编译器知道后续是否还用） |

**为什么中断要存 PSW、函数调用不用（第 18 题的核心）**：C 语言的 `if (a == b)` 会编译成两条指令——第一条 `CMP` 做减法但**不保存结果，只置标志位**；第二条按标志位条件跳转。若 CMP 执行完、跳转还没执行时来了中断，中断服务程序可能改写标志寄存器，返回后就会按**错误的标志位**跳转，所以必须保存 PSW。而调用函数时，一定是"标志位已经用完、已经完成跳转"才进入函数，标志位已无意义。

**为什么函数调用不一定保存通用寄存器**：编译器知道被调函数会改哪些寄存器、调用后主程序还用不用某个值。若变量 X 放在 R1，调用 F 后还要用 X，编译器就把 R1 压栈；若 F 之后 X 不再使用，就不保存。

### 四、系统调用（1.3 重点）

**定义**：操作系统提供给应用程序的**程序接口**，是内核功能的**间接**调用入口；用户程序通过它请求操作系统代为完成自己无权完成的操作，完成后通常返回应用程序。

**为什么要系统调用**：用户程序无权直接访问外部设备等资源，若人人自写底层代码，极易出错、破坏系统；由 OS 统一封装、统一把关。

**系统调用号**：每个系统调用有**唯一编号**，内核据此查表分派，思想与"中断类型号"完全一致。

**常见系统调用**（对应后续章节）：文件操作（open/read/write/close）、进程创建与撤销、内存分配、设备请求。

**执行过程（步骤链，必须背）**：

```text
用户程序
  ↓ ① 传递参数（系统调用号 + 所需参数，放入寄存器/堆栈/指定内存区）
  ↓ ② 执行陷入指令 trap（★在用户态执行，执行完才进入内核态）
  ↓ ③ 硬件保存现场（保存 PC、PSW 等断点），PSW 模式位改为内核态
  ↓ ④ 内核按系统调用号查入口表，转入对应服务例程
  ↓ ⑤ 内核态执行服务例程（真正的处理）
  ↓ ⑥ 恢复现场
  ↓ ⑦ 执行返回指令（特权指令，在内核态执行）→ 回到用户态
```

注意：**用户态 → 内核态靠 trap；内核态 → 用户态靠返回指令**，两条方向不同的指令不要混。

**系统调用 vs 普通过程调用**：

| 对比项 | 系统调用 | 普通过程调用 |
|---|---|---|
| 运行状态 | 调用者在用户态，被调用者在内核态（**跨特权级**） | 同一特权级（用户态调用户态、内核态调内核态） |
| 状态转换 | 有：trap 引发用户态→内核态 | 无 |
| 返回 | 执行完由内核按调度策略决定是否切换进程，**不一定立即返回** | **总是**返回原调用点 |
| 主动性 | **主动**（程序员写代码主动请求） | 主动 |

**系统调用 vs 中断/异常**：系统调用是**主动**的（执行到该行，主动要求进内核办事）；中断和异常是**被动**的（出错或外部请求，被迫进入内核）。

### 五、1.4–1.6 体系结构、引导与虚拟机（课程第一轮跳过，下列为教材补充）

> 课程明确说明：1.4～1.6 属"边角知识"，需背大量规则且会用到后续章节内容，**第一轮直接跳过，强化阶段再补**；06 这一 P 只有约 1 分钟说明，无实质知识点。以下为教材补充，仅作框架性了解，不作为本笔记的课程内容。

**（教材补充）大内核 vs 微内核**：

| 对比项 | 大内核（单体内核） | 微内核 |
|---|---|---|
| 结构 | 操作系统主要功能模块都放入内核 | 只保留最基本功能（进程通信、低级调度、中断处理）在内核 |
| 性能 | **高**（模块间直接函数调用，少态切换） | **低**（频繁的用户态/内核态切换、消息传递开销） |
| 可靠性/可维护性 | 低（一处出错整机崩溃，代码庞大难维护） | **高**（服务进程崩溃可重启，内核小而稳） |
| 典型 | Linux、UNIX | Mach、QNX |

其他结构（教材补充）：分层结构（层间单向依赖，调试容易但效率低）、模块化（内核可动态加载模块）、外核（把硬件资源直接分配给用户进程）。

**（教材补充）操作系统引导**：CPU 加电 → 执行 BIOS 自举程序 → 读取启动设备的**主引导记录 MBR** → 执行分区引导记录 → 加载**活动分区**的引导程序 → 装入操作系统内核并初始化。课程提到"引导"曾在某年考过一次**大题**，强化阶段会专门讲。

**（教材补充）虚拟机**：第一类 VMM 直接运行在硬件上（如 Xen、VMware ESXi）；第二类 VMM 运行在宿主操作系统之上（如 VMware Workstation）。虚拟机也是"虚拟"思想的延伸。

### 六、（课程在 3.1.1 讲过，此处提前收录）程序的链接与装入

> 这部分严格说属第 3 章 3.1.1，但课程确实讲了完整规则与数字例子，为对比"逻辑地址/物理地址"提前收录。

**三种链接方式**：

| 方式 | 时机 | 特点 |
|---|---|---|
| 静态链接 | **程序运行前**，把各目标模块和所需库函数合并成一个完整装入模块（可执行文件） | 一次成型，运行时不再链接 |
| 装入时动态链接 | **装入内存的同时**边装入边链接 | 未执行的模块也会被装入并链接 |
| 运行时动态链接 | **执行中真正用到某模块时**才装入并链接 | 节省内存，未用模块不装入 |

**三种装入方式**：

| 方式 | 地址变换 | 特点 | 适用 |
|---|---|---|---|
| 绝对装入 | 逻辑地址 = 物理地址，装入时不改 | 简单，地址写死 | **单道程序**环境（多道会地址冲突） |
| 可重定位装入（**静态重定位**） | 装入时**一次性**把全部逻辑地址 + 起始地址改成物理地址 | 装入后**运行期间不能移动** | 多道、连续分配 |
| 动态运行时装入（**动态重定位**） | 装入时不改地址，**执行时**由**重定位寄存器**（存模块起始物理地址）+ 逻辑地址 相加得到物理地址 | 程序在内存中**可以移动** | 支持分页/分段、虚拟内存 |

**静态重定位数字例子**：进程逻辑地址从 0 开始，指令 `LOAD 6` 取变量 A（相对地址 6），`ADD 8` 取变量 B（相对地址 8）。装入到**从 100 开始**的内存后，装入程序把指令改成 `LOAD 106`、`ADD 108`，A 在 106、B 在 108。此时若把进程搬到 200 开始，指令里写死的 106 就错了——所以**装入后不能移动**。

**动态重定位数字例子**：指令里仍写 `LOAD 500`（相对地址），装入到 **1000** 开始处，重定位寄存器 = 1000，实际访问 **1000 + 500 = 1500**；某时刻把进程移到 **2000** 开始，只需把重定位寄存器改成 2000，实际访问 **2500**，指令本身不用动——所以**可以移动**。

**（教材补充）内存保护**（课程在第 3 章讲，此处仅列结论）：①上下限寄存器：P2 占 400～499，访问 150 越界、访问 450 合法；②重定位（基址）寄存器 + 界地址（限长）寄存器：存 400 和长度 100，相对地址 50 合法 → 物理地址 400+50=450，相对地址 150 ≥ 100 则越界。

## 快速技巧与口诀

- **三对概念成对背**：用户程序↔非特权指令↔用户态；内核程序↔特权指令↔内核态。
- **PSW 位记法**："**0 内核、1 用户**"（0 像"官印"，内核最大）。
- **状态转换口诀**："**进内核靠中断异常，出内核靠返回指令；trap 在用户态，改模式靠硬件**"。
- **九个步骤口诀**："**关、存、引**（硬件三步）→ **保、析、处、恢、开、返**（OS 六步）"。
- **内外中断判别法**：问"这事是不是当前这条指令自己惹出来的？"是→内中断（异常）；不是（外部设备/时钟/电源）→外中断。
- **故障/自陷/终止判别法**：能修好重执行→故障；主动陷入、执行完往下走→自陷；修不了、程序死→终止。
- **系统调用四步**："**传参 → 陷入 → 处理 → 返回**"，与"函数调用"只差"跨特权级"三个字。
- **"越多越高"必错**：多道程序数 ↑，CPU 利用率不会无限 ↑（切换有开销）。
- **做题策略**：概念题做完无论对错都要读解析、回读书上原文；真题反复考的点优先背。

## 易错点与坑

1. **"内核态只能执行特权指令"——错**。内核态权限高，特权指令和非特权指令都能执行；只是**用户态不能执行特权指令**。
2. **"trap 是特权指令 / 在内核态执行"——错**。trap 是非特权指令，在**用户态**执行，执行完才切换到内核态。
3. **"中断在用户态发生所以在用户态处理"——错**。发生可以在用户态，**处理一定在内核态**。
4. **"系统调用不属于中断/异常"——错**。系统调用属于**自陷（内中断/异常）**，所以"用户态→内核态只能通过中断或异常"这句话仍然成立。
5. **"缺页是外中断"——错**。缺页是执行指令访存时才发现，属**内中断（故障）**，可修复，返回**当前指令**重执行。
6. **"除零是自陷"——错**。除零是**故障**，且是**不可修复**的故障，通常终止程序。
7. **"保存断点是操作系统做的"——错**。保存断点（PC、PSW）、关中断、引出中断服务程序都由**硬件**完成；保存通用寄存器才是 OS 做。
8. **"把 CPU 模式改为内核态是 OS 做的"——错**。由**硬件**完成。
9. **"系统调用一定马上返回"——错**。内核可能按调度策略切换进程，只有普通过程调用才总返回原调用点。
10. **"并行 = 并发"——错**。单 CPU 上多个程序只能并发；CPU 与 I/O、多个 I/O 设备之间才是并行。
11. **"同时访问 = 真正同时"——错**。同时访问宏观同时、**微观仍是交替**（磁盘按字节轮流读写）。
12. **"printf 是系统调用"——错**。printf 是库函数，内部封装 write 系统调用。
13. **"多道程序数越多 CPU 利用率越高"——错**。切换需保存/恢复现场，开销随道数增加。
14. **"批处理有交互性"——错**。单道、多道批处理都**没有**交互性；有交互性的是分时和实时。
15. **"内中断 = 硬件中断"——错**。内中断（异常）中故障与自陷又叫**软件中断**；硬件中断 = 终止 + 外中断。

## 本章例题

**1（1.2 题单 17）关于批处理系统的说法**
要点：①批处理没有交互性；②单处理器下 CPU 可并行执行多个程序；③I/O 设备与 CPU 可并行；④多道系统资源利用率高。
解：①对——单道从头跑到尾、多道要等前程序让出 CPU，都无交互；②错——单 CPU 只能**并发**（交替），不能并行；③对——CPU 跑 P1 的同时打印机可为 P4 工作，属并行；④对。
答案：①③④正确，②错误。

**2（1.2 题单 18）多道批处理系统的优点**
要点：①CPU 利用率高；②系统开销小；③系统吞吐量大；④I/O 设备利用率高。
解：①对（CPU 一空出就换程序）；③对（交替执行多道，吞吐量大）；④对（P1 不用 I/O 立刻给 P2）；②错——进程切换要保存/恢复现场（PC、PSW、寄存器），**开销变大**。
答案：①③④（即"134"）。

**3（1.2 题单 19）多任务操作系统**
要点：是否需要多 CPU、是否能并发/并行、是否要保护共享资源。
解：单 CPU 也能**并发**；CPU 与 I/O 之间可**并行**；多任务必然共享打印机等资源，必须做**互斥保护**（否则文档打印错乱）；**不需要**多 CPU。
答案：C（具备并发与并行能力、需对共享资源保护；不要求多 CPU）。

**4（1.2 题单 20）关于多道程序**
要点：能否支持并发、是否必须支持虚拟存储、CPU 利用率是否随道数线性提高。
解：可支持并发（对）；虚拟存储不是必需的（对）；"多道程序越多 CPU 利用率越高"（**错**，切换有开销）。
答案：D 错误。

**5（题单 16）在用户态执行的是**
选项性质：命令解释程序 / 缺页处理程序 / 时钟中断处理程序 / 进程调度程序。
解：凡"××处理程序""调度程序"都是操作系统内核代码，必在内核态；命令解释程序只是解释用户敲的命令，不需高权限。
答案：**命令解释程序**。

**6（题单 17）在用户态发生的是**
解：关键在"发生"。缺页是用户态执行指令访存时发现的（发生在用户态），随后进内核态执行缺页处理程序（处理在内核态）；进程切换、中断处理都在内核态执行。
答案：**缺页**（发生于用户态）。

**7（题单 19）从用户态切换到内核态的情形**
①整数除零 ②调用 sin() 库函数 ③系统调用。
解：①除零→内中断，切换；②sin() 是普通数学运算，用户态完成，不切换；③系统调用→自陷，切换。
答案：**①③**。

**8（题单 22）可能引起用户态→内核态的操作**
A 两数相除；B 取某地址的内容送入寄存器；C 寄存器内容取反。
解：A 可能除数为 0 → 故障；B 该地址可能缺页或越界 → 故障；C 是纯算术逻辑运算，永不出错。
答案：**A、B**。

**9（题单 20）不能在用户态执行的是**
选项含 trap 指令、跳转指令、压栈指令、关中断指令。
解：trap 在用户态执行；跳转、压栈是普通指令；关中断权限高，是特权指令。
答案：**关中断**。

**10（题单 23）中断分类判断**
缺页、整数除零、DMA 结束、存储保护错。
解：缺页——执行指令访存才发现，内中断（异常/故障）；除零——内中断（异常/故障）；DMA 结束——I/O 设备发来的外部信号，外中断；存储保护错——访问越界，执行指令时发现，内中断（异常）。
答案：缺页、除零、存储保护错为**内中断**；DMA 结束为**外中断**。

**11（题单 24）系统调用的执行顺序**
①返回用户态 ②执行 trap ③传参 ④执行服务程序。
解：先传参（调用号+参数）→ trap 进内核 → 执行服务例程 → 返回。
答案：**③→②→④→①**。

**12（题单 26）关于系统调用**
解：①执行系统调用时处于内核态——对；②操作系统通过系统调用避免用户程序直接访问外部设备——对；③不同操作系统提供统一接口——**错**（Windows、macOS、Android 接口各不同）；④系统调用是 OS 为应用程序提供服务的接口——对。
答案：**③错误**。

**13（题单 27）由操作系统完成的操作**
①保存断点 ②初始化中断向量表 ③设置中断屏蔽字 ④保存通用寄存器。
解：①硬件完成；②③④由 OS 完成（初始化向量表、设屏蔽字决定多重中断优先级、保护现场）。
答案：**②③④**。

**14（题单 28）只能在内核态执行的是**
解：trap 在用户态；数据传送、设置断点属非特权；**I/O 指令**访问端口，是特权指令。
答案：**I/O 指令**。

**15（题单 29）通过系统调用完成的是**
解：进程调度、页面置换由 OS 后台自动完成，不是用户主动申请；生成随机数是用户态数学运算；**创建新进程**必须由用户主动调用系统调用。
答案：**创建新进程**。

**16（题单 30）判断："内核态只能执行特权指令"**
解：内核态权限更高，特权指令能执行，非特权指令也能执行。
答案：**错误**。

**17（题单 31）系统调用过程中由操作系统完成的操作**
①保存断点 ②保存通用寄存器 ③执行系统调用 ④把 CPU 模式改为内核态。
解：①④由硬件完成；②③由 OS 完成。
答案：**②③**。

**18（题单 32）中断向量表**
解：本质是数组，下标为中断类型号，表项为该类型中断服务程序的入口地址（中断向量），这样才能按类型号快速定位。
答案：描述"数组 + 类型号 + 入口地址"的选项正确。

**19（题单 33）中断/异常的状态判定**
解：A "中断或异常发生时处于内核态"——**错**，发生时在用户态，处理时才在内核态；B "每个系统调用都有对应的内核服务例程"——对；C 中断处理程序在内核态执行——对；D 新增设备需注册对应中断服务例程——对。
答案：**A 错误**。

**20（题单 18，偏难）中断处理与子程序调用的保存差异**
解：①PC：两者都要保存（都要返回）；②PSW：中断必须保存（CMP 置的标志位可能在中断服务程序中被改写，返回后按错标志跳转），子程序调用不需保存（标志位在跳转进函数时已用完）；③通用寄存器：中断必须保存（第 4 步保护现场，一个高级语言语句展开成多条指令，执行一半被打断），子程序**不一定**（编译器知道后续是否还用，如 X 在 R1、调用 F 后还要用 X 才保存）。
答案：PC 都保存；PSW 仅中断保存；通用寄存器仅中断必须保存。
