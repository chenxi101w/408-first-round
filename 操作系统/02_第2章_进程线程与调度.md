## 知识点详解

### 一、进程的概念与组成（2.1.1、2.1.2）

**定义**：进程是程序在一个数据集合上的一次运行过程，是系统进行**资源分配**和（引入线程前）**调度**的独立单位。

**进程实体（进程映像）= 程序段 + 数据段 + PCB**，三者缺一不可：

| 组成 | 内容 | 作用 |
|---|---|---|
| 程序段 | 一条条机器指令（操作码 + 地址码） | 说明"做什么" |
| 数据段 | 指令通过地址码访问的数据、全局变量 | 处理的对象 |
| PCB | 进程控制块 | 操作系统用它**控制和管理**进程 |

**PCB 是进程存在的唯一标志**，进程创建时建立 PCB，进程终止时回收 PCB；PCB 常驻内存（不换出到外存）。

**PCB 的内容（表 2.1 勾重点，四类）**：

| 类别 | 具体字段 | 说明 |
|---|---|---|
| 进程描述信息 | 进程标识符 PID、用户标识符 UID、父进程 PID | 任务管理器里每个进程的 ID |
| 进程控制和管理信息 | 当前状态、优先级、已占用 CPU 时间、信号量使用情况 | 调度与状态判定依据 |
| 资源分配清单 | 内存地址空间/页表指针、**打开文件列表（文件描述符表）**、占用的 I/O 设备 | 资源回收的依据 |
| 处理机相关信息（现场） | **通用寄存器、程序计数器 PC、程序状态字 PSW、栈指针** | 切换后能"接着上次断点"跑 |

> 老师原话：这几个（通用寄存器、PC、PSW、栈指针）先画上，栈指针、文件描述符要学到第 3、4 章才懂，但**考试要能认出来它们属于 PCB**。

**进程的特征**（只需记第一条）：**动态性是最本质的特征**——进程是程序的一次执行，每时每刻状态都在变；程序是静态的、写死的代码。

- 一份静态代码可以对应多个进程：QQ 双击多次 → 多个进程，各登不同账号，数据互不相同。
- 用任务管理器看：同一进程的 CPU 占用率每秒都在跳，这就是动态性。

**进程的虚拟地址空间**（图 2.1，2025 年考过大题，基础阶段只需记住区域名）：自低地址到高地址依次为**只读代码区、读写数据区、堆、共享函数库、用户栈、内核区**。每个进程都有独立的虚拟地址空间，都从 0 开始编址；进程的数据私有，保证进程间独立性。

### 二、进程的状态与转换（2.1.3）★核心

#### 1. 三种基本状态

| 状态 | 定义 | 判别口诀 |
|---|---|---|
| 运行态 | 正占用 CPU 执行 | 单 CPU 任一时刻**最多一个** |
| 就绪态 | 已获得除 CPU 外的全部资源，只差 CPU | "万事俱备，只欠 CPU" |
| 阻塞态 | 因等待某事件（I/O 完成、资源可用、信号量）而暂停 | "即使给 CPU 也跑不了" |

- **阻塞 = 让出 CPU**：进程一旦阻塞，会主动把 CPU 交出来（如打印要等很久，不能占着 CPU 空转）。
- 阻塞的两种典型成因：① 自己发起 I/O，等 I/O 完成；② 申请的资源被别人占着（P1 正用打印机，P2 申请就得阻塞）。
- 系统中维护**就绪队列**和**阻塞队列**（多个阻塞队列，按等待事件排队）。

#### 2. 五状态转换图（文字化）

```
                   ①资源就位(除CPU)            ②被调度,获得CPU
   [创建态] ─────────────────────→ [就绪态] ─────────────────→ [运行态]
                                     ↑   ←─────────────────┐      │
                                     │  ③时间片完/被更高优先级抢占   │
                                     │                        │④主动请求I/O、
                                     │                        │  申请资源失败、
                                     │                        │  P操作
                                     │                        ↓
                                     └────⑤事件完成(唤醒)─── [阻塞态]
                                                              
   [运行态] ──⑥正常结束/异常终止/被kill──→ [终止态]
```

**每条边的事件（背这张表）**：

| 编号 | 边 | 触发事件 | 主动/被动 |
|---|---|---|---|
| ① | 创建 → 就绪 | 申请 PCB、分配内存等资源完毕（只差 CPU） | 系统 |
| ② | 就绪 → 运行 | 被进程调度程序选中，分配 CPU | 被动（被选中） |
| ③ | 运行 → 就绪 | 时间片用完；被更高优先级进程抢占；主动让出 CPU | 时间片到=被动；yield=主动 |
| ④ | 运行 → 阻塞 | 启动 I/O（读磁盘/打印）、申请临界资源失败、申请内存失败、P 操作、等待信号量 | **主动**（自己把自己阻塞） |
| ⑤ | 阻塞 → 就绪 | I/O 完成、中断处理程序唤醒、V 操作、别的进程退出临界区释放资源 | **被动**（被别人唤醒） |
| ⑥ | 运行 → 终止 | 正常结束（main 返回）、异常终止、强制杀死 | —— |

> 老师强调：**④ 是主动、⑤ 是被动**，这是选择题最爱设的陷阱。"阻塞态 → 就绪态"这个过程叫**唤醒**。

**不可能发生的转换（选择题反复考）**：

| 转换 | 为什么不可能 |
|---|---|
| 就绪 → 阻塞 | 没占 CPU，发不起 I/O 请求，也就无从阻塞 |
| 阻塞 → 运行 | 缺 CPU 又缺事件，必须先回就绪队列排队 |
| 创建 → 运行 | 资源未分配完，必须先就绪 |
| 就绪 → 终止 | 没运行过，谈不上"执行结束"（教材口径） |
| 阻塞 → 终止 | 一般要先唤醒再终止（教材口径；kill 强杀属实现细节，不选） |

#### 3. 七状态模型（加入挂起）

内存紧张时，中级调度把暂不运行的进程**换出到外存**，状态变为"挂起"（静止）；内存有空且具备运行条件时再**换入**（激活）。

```
   就绪态 ──⑦挂起──→ 挂起就绪态 ──⑧激活──→ 就绪态
     │                                       
   运行态 ──④──→ 阻塞态 ──⑦挂起──→ 挂起阻塞态 ──⑧激活──→ 阻塞态
                                          │
                                          └──⑨等待的事件发生──→ 挂起就绪态
```

| 新增边 | 事件 |
|---|---|
| 就绪 → 挂起就绪 | 中级调度换出（内存紧张）、用户挂起（调试）、父进程请求 |
| 阻塞 → 挂起阻塞 | 同上（阻塞进程也可能被换出，因为它的 PCB 之外的数据可换出） |
| 挂起就绪 → 就绪 | 激活（换入内存），具备运行条件 |
| 挂起阻塞 → 阻塞 | 激活，但事件仍未完成 |
| 挂起阻塞 → 挂起就绪 | 等待的事件发生了（如 I/O 完成），但仍在外存 |

**七状态下仍不可能**：挂起就绪 → 运行（必须先换入变就绪）；挂起阻塞 → 运行；挂起就绪 → 阻塞（没 CPU，不能发起 I/O）。

### 三、进程控制（2.1.4）

进程控制通过**原语**（不可中断）实现，本质是"改 PCB + 改队列 + 改资源"。

| 操作 | 触发者 | 主要动作 |
|---|---|---|
| 创建 | 用户登录、作业调度、父进程 fork | 申请 PCB → 分配内存等资源 → 初始化 PCB → 插入就绪队列 |
| 终止 | 正常结束、异常、外界干预 | 回收资源 → 撤销 PCB；**某些系统中父进程终止，其所有子进程也必须终止**（并非所有 OS 都这样） |
| 阻塞 | 进程自身（**只有运行态进程能执行阻塞原语**） | 保存现场到 PCB → 置阻塞态 → 插入相应阻塞队列 → 转调度 |
| 唤醒 | 别的进程/中断处理程序 | 从阻塞队列摘出 → 置就绪态 → 插入就绪队列 |

### 四、进程通信（2.1.5，课上跳过，以下为教材补充）

| 方式 | 做法 | 适用/优点 | 限制/缺点 |
|---|---|---|---|
| 共享存储 | 申请一块共享内存区，双方直接读写 | 速度最快（不走内核拷贝），适合大数据量 | 必须**自己加同步互斥**（信号量/PV），否则数据错乱；基于共享数据结构时速度更低 |
| 消息传递 | 以"消息"为单位，通过 send/receive 原语经内核转发 | 无需共享地址空间，**可用于分布式系统/网络**；直接通信（指名道姓）或间接通信（信箱） | 每次都要陷入内核、拷贝，开销大于共享存储；消息有格式与队列管理成本 |
| 管道 pipe | 内核中一个**固定大小的缓冲区**，按字节流先进先出 | 实现简单，天然同步（写满则写进程阻塞，读空则读进程阻塞） | **半双工**（某一时刻单向，双向需两条）；匿名管道只能用于**有亲缘关系**的进程；数据一旦被读走就消失，不能随机访问 |

- **低级通信**：PV 操作，只能传少量信息（信号），主要解决同步互斥；**高级通信**：共享存储、消息传递、管道，能传大量数据。
- 管道读写的边界：缓冲区空 → 读阻塞；缓冲区满 → 写阻塞；写端全部关闭 → 读返回 0（EOF）。

### 五、线程与多线程模型（2.1.6）★核心

**定义**：线程是"轻量级进程"，是**CPU 调度的基本单位**；进程仍是**资源分配的基本单位**。

**为什么引入线程**（老师举的例子）：QQ 一个进程里既有语音电话又有聊天。若只有进程，代码只能从头执行到尾——必须先打完语音才能聊天；有了线程，语音一个线程、聊天一个线程，单 CPU 上交替执行像"同时进行"，多 CPU 上还能真正并行（一个进程的多个线程可分到多个核）。好处：**提高并发性、减小切换开销、充分利用多核**。

#### 1. 线程共享什么、独有什么（必须列全）

| 类别 | 内容 |
|---|---|
| **同进程内所有线程共享**（属于进程） | 进程的**地址空间**（代码段、数据段）、**全局变量/静态变量**、**堆**、**打开的文件与文件描述符表**、当前工作目录、进程 PID、信号处理函数、进程的锁/信号量等资源 |
| **每个线程私有** | **线程 ID**、**程序计数器 PC**、**通用寄存器组**、**栈（及栈指针）**、**线程状态**、优先级、局部变量、错误码 errno、线程私有数据 |

记忆：**"栈私有、堆共享；代码全局文件共享；PC 寄存器 ID 状态私有"**。
2011 年考"线程不能共享栈指针"，2024 年考"线程 T 打开的文件描述符可被同进程其他线程共享"——**文件描述符登记在进程的 PCB 里，所以共享**。

#### 2. 线程与进程对照表

| 维度 | 进程 | 线程 |
|---|---|---|
| 定位 | 资源分配的基本单位 | CPU 调度的基本单位 |
| 地址空间 | 每个进程独立 | 同进程线程共用进程地址空间 |
| 拥有的资源 | 拥有全部系统资源 | 基本不拥有资源，只保留私有现场 |
| 并发性 | 进程间可并发 | 同进程线程可并发，不同进程的线程也可并发 |
| 切换开销 | 大（要切换地址空间、页表、TLB 失效） | 小（同进程内切换只保存/恢复寄存器，地址空间不变） |
| 独立性 | 高，一个进程崩溃不影响别的进程 | 低，一个线程崩溃可能拖垮整个进程 |
| 控制块 | PCB | TCB（线程 ID、寄存器、状态、优先级、私有数据、栈指针） |
| 状态 | 创建/就绪/运行/阻塞/终止 | 同样有这五种，转换关系与进程一致 |

#### 3. 用户级线程 vs 内核级线程

| 维度 | 用户级线程（ULT） | 内核级线程（KLT） |
|---|---|---|
| 管理者 | **用户空间的线程库**，操作系统看不见 | **操作系统内核** |
| 创建/切换/撤销 | 全在**用户态**完成，不需陷入内核 | 必须在**内核态**完成 |
| 切换开销 | 小（不进内核，效率高） | 大（用户态→内核态，中断/陷入） |
| 阻塞影响 | **一个线程阻塞（如 I/O）会导致整个进程阻塞**，内核只看到进程 | 一个线程阻塞，同进程其他线程仍可运行 |
| 多核利用 | 不能，内核按进程调度，只能分到一个 CPU | 可以把同进程多个线程分到多个 CPU 并行 |
| 内核支持 | 不需要（可在不支持线程的 OS 上跑） | 必须有内核支持 |
| 典型 | 早期线程库 | Windows、Linux（NPTL） |

- **多对一**：多个用户级线程映射到一个内核线程 → 并发度高但一阻塞全阻塞、不能用多核。
- **一对一**：每个用户线程对应一个内核线程 → 并发能力最强，线程数受内核限制、开销大。
- **多对多**：n 个用户线程映射到 m 个内核线程（n ≥ m）→ 折中方案。

### 六、CPU 调度的基本概念（2.2.1）

**调度**：CPU 按某种规则从**就绪队列**中选一个进程，把 CPU 分配给它。

| 层次 | 别名 | 做的事 | 频率 |
|---|---|---|---|
| 高级调度 | 作业调度 | 从**外存**后备队列选作业调入**内存**，创建进程（外存→内存） | 最低 |
| 中级调度 | 内存调度/交换调度 | 把暂不运行的进程**挂起**换出外存，需要时换入（内存↔外存） | 中 |
| 低级调度 | 进程调度 | 从就绪队列选进程上 CPU，**本章核心** | 最高（几十 ms 一次） |

> "作业"就当"任务/请求"理解，考试不专门区分作业/程序/进程三个词。

**进程切换要做的事**：保存当前进程现场（寄存器值、PC、PSW）到它的 PCB → 恢复被选中进程的现场到 CPU 寄存器 → 使其从断点继续执行。**上下文切换有开销**（这也是时间片不能太小的原因）。

### 七、调度时机、方式与上下文切换（2.2.2、2.2.3）

**会引起调度（或可能引起）的情形**：进程正常/异常终止；进程阻塞（主动让出 CPU）；时间片用完；有更高优先级进程到达（抢占式）；进程主动 yield。

**不能进行调度的情形**：① **正在处理中断**（中断处理程序属于内核，必须一口气处理完）；② 进程处于**内核临界区/原子操作**中（如修改就绪队列、PV 操作内部），否则会破坏内核数据结构。

**闲逛进程（idle）**：系统中没有就绪进程时，内核让 idle 进程占着 CPU，避免 CPU 空转。特点：**优先级最低**、**不占用 CPU 以外的其他资源**、**永远不会阻塞**。

**两种调度方式**：

| 方式 | 别名 | 规则 | 后果 |
|---|---|---|---|
| 非抢占式 | 非剥夺式 | 进程一旦上 CPU 就一直跑到**结束或阻塞**才让出，即使来了更高优先级的 | 开销小、实现简单；实时性差 |
| 抢占式 | 剥夺式 | 只要有更紧迫（更高优先级/时间片到）的进程，立刻剥夺当前进程的 CPU | 响应快；切换频繁、开销大、需同步保护 |

**模式切换 vs 上下文切换**（易混）：

| | 模式切换 | 上下文切换 |
|---|---|---|
| 含义 | 同一进程内 用户态 ↔ 内核态 | 从一个进程切换到另一个进程 |
| 是否换进程 | 否，还是同一个进程 | 是 |
| 开销 | 较小（只换栈和 PSW） | 较大（保存/恢复现场 + 换地址空间、页表、TLB 刷新） |

### 八、调度评价指标（2.2.4）★必背公式

设进程 i 的到达（提交）时间为 $a_i$，服务（运行）时间为 $s_i$，完成时间为 $f_i$。

| 指标 | 公式 | 说明 |
|---|---|---|
| CPU 利用率 | 工作时间 ÷ 总时间 | 例：10 s 内工作 5 s → 50% |
| 周转时间 | $T_i = f_i - a_i$ | 从提交到完成的总时间（含等待 + 运行） |
| 平均周转时间 | $\bar T = \frac{1}{n}\sum T_i$ | 最常考 |
| 带权周转时间 | $W_i = T_i / s_i$ | 恒 ≥ 1，越接近 1 越好 |
| 平均带权周转时间 | $\bar W = \frac{1}{n}\sum W_i$ | 短作业被拖延时该值会爆炸 |
| 等待时间 | $W\!t_i = T_i - s_i$ = 各段等待之和 | 可能由多段组成 |
| 响应时间 | 首次执行时刻 − 提交时刻 | **只算第一段等待** |

> 等待时间 vs 响应时间（老师专门对比）：某进程 t=2 提交，t=7 首次运行，运行到 9 被停，t=20 又运行。响应时间 = 7−2 = 5；等待时间 = (7−2) + (20−9) = 5 + 11 = 16（**多段求和**）。

### 九、调度算法逐个 + 算例（2.2.5）★

**做题固定动作：画甘特图（横轴时间、纵轴进程），再由图读完成时间。** 老师反复强调：选项是数字的题必须画图。

#### 1. FCFS 先来先服务

规则：按进入就绪队列的先后分配 CPU，**非抢占**。谁先到谁先跑，运行中不会被打断。
缺点：**护航效应**——先到的长作业把后面一堆短作业全堵住。

**算例**（教材补充）：

| 进程 | 到达 | 服务 |
|---|---|---|
| P1 | 0 | 7 |
| P2 | 2 | 4 |
| P3 | 4 | 1 |
| P4 | 5 | 4 |

甘特图：`P1[0-7] | P2[7-11] | P3[11-12] | P4[12-16]`

| 进程 | 到达 | 服务 | 开始 | 完成 | 周转 T | 带权 W=T/s | 等待 |
|---|---|---|---|---|---|---|---|
| P1 | 0 | 7 | 0 | 7 | 7 | 1.00 | 0 |
| P2 | 2 | 4 | 7 | 11 | 9 | 2.25 | 5 |
| P3 | 4 | 1 | 11 | 12 | 8 | 8.00 | 7 |
| P4 | 5 | 4 | 12 | 16 | 11 | 2.75 | 7 |

平均周转 = 35/4 = **8.75**；平均带权 = 14/4 = **3.50**；平均等待 = 19/4 = **4.75**。
对比：同样数据用 SJF（P1→P3→P2→P4），平均周转 = 32/4 = **8.00**，可见 FCFS 被短作业"陪跑"拖累。

#### 2. SJF 短作业（短进程）优先 —— 非抢占

规则：每次从就绪队列选**服务时间最短**的进程。**默认非抢占**，但也可以做成抢占式（老师原话："题目没说就默认非抢占，它也可以是抢占的"）。

**算例（老师课上原题，4 个作业）**：

| 作业 | 提交时间 | 运行时间 |
|---|---|---|
| 1 | 8 | 2 |
| 2 | 8.4 | 1 |
| 3 | 8.8 | 0.5 |
| 4 | 9 | 0.2 |

甘特图：`1[8-10] | 4[10-10.2] | 3[10.2-10.7] | 2[10.7-11.7]`
t=8 只有作业 1 到达 → 先跑 1 到 10；t=10 时 2、3、4 都已到达，按运行时间 0.2 < 0.5 < 1 依次排 4→3→2。

| 作业 | 提交 | 运行 | 开始 | 完成 | 周转 T | 带权 W | 等待 |
|---|---|---|---|---|---|---|---|
| 1 | 8 | 2 | 8 | 10 | 2 | 1.0 | 0 |
| 2 | 8.4 | 1 | 10.7 | 11.7 | 3.3 | 3.3 | 2.3 |
| 3 | 8.8 | 0.5 | 10.2 | 10.7 | 1.9 | 3.8 | 1.4 |
| 4 | 9 | 0.2 | 10 | 10.2 | 1.2 | 6.0 | 1.0 |

平均周转 = 8.4/4 = **2.1**；平均带权 = 14.1/4 = **3.525**；平均等待 = 4.7/4 = **1.175**。

#### 3. SRTF 最短剩余时间优先（抢占式 SJF）

规则：新进程到达时，若其服务时间 **< 当前进程的剩余时间**，立即抢占。**抢占**。

**算例**（教材补充）：

| 进程 | 到达 | 服务 |
|---|---|---|
| P1 | 0 | 8 |
| P2 | 1 | 4 |
| P3 | 2 | 9 |
| P4 | 3 | 5 |

逐步推演：
- t=0 只有 P1 → P1 运行；
- t=1 P2 到达，服务 4 < P1 剩余 7 → **抢占**，P2 运行 1→5 结束；
- t=5 就绪：P1 剩 7、P3 需 9、P4 需 5 → 选 P4，5→10 结束；
- t=10 P1 剩 7 < P3 需 9 → P1 运行 10→17 结束；
- t=17 只剩 P3 → 17→26 结束。

甘特图：`P1[0-1] | P2[1-5] | P4[5-10] | P1[10-17] | P3[17-26]`

| 进程 | 到达 | 服务 | 完成 | 周转 T | 带权 W | 等待 |
|---|---|---|---|---|---|---|
| P1 | 0 | 8 | 17 | 17 | 2.125 | 9 |
| P2 | 1 | 4 | 5 | 4 | 1.000 | 0 |
| P3 | 2 | 9 | 26 | 24 | 2.667 | 15 |
| P4 | 3 | 5 | 10 | 7 | 1.400 | 2 |

平均周转 = 52/4 = **13.0**；平均带权 = 7.192/4 = **1.798**；平均等待 = 26/4 = **6.5**。

#### 4. HRRN 高响应比优先（老师要求记公式）

$$\text{响应比 } R=\frac{\text{等待时间}+\text{服务时间}}{\text{服务时间}}=\frac{\text{等待时间}}{\text{服务时间}}+1$$

等待越久 R 越大（防饥饿），服务越短 R 越大（偏好短作业）。**非抢占**，每次调度时重算所有就绪进程的 R，选最大者。

**算例**（教材补充）：A(0,3)、B(2,6)、C(4,4)、D(6,5)

- t=0 只有 A → A 跑 0-3；
- t=3 只有 B → B 跑 3-9；
- t=9：C 等待 5，R=(5+4)/4=2.25；D 等待 3，R=(3+5)/5=1.6 → 选 C，9-13；
- t=13 只剩 D → 13-18。

| 进程 | 到达 | 服务 | 完成 | T | W | 等待 |
|---|---|---|---|---|---|---|
| A | 0 | 3 | 3 | 3 | 1.000 | 0 |
| B | 2 | 6 | 9 | 7 | 1.167 | 1 |
| C | 4 | 4 | 13 | 9 | 2.250 | 5 |
| D | 6 | 5 | 18 | 12 | 2.400 | 7 |

平均周转 = 31/4 = **7.75**；平均带权 = 6.817/4 = **1.704**。

#### 5. 优先级调度

规则：每个进程有优先级，**优先级最高者先运行**。分**抢占式**（更高优先级一到就抢）和**非抢占式**（当前进程跑完或阻塞才换）。

- **静态优先级**：创建时确定，运行期间不变；**动态优先级**：随等待时间增长而提高（防饥饿）。
- 一般设定：**交互型进程 > 非交互型进程**（要快速响应）；**I/O 型进程 > 计算型进程**（I/O 设备慢，让它尽早启动 I/O，CPU 与 I/O 并行）。
- **饥饿**：低优先级进程可能长期得不到调度。

**算例（课后 53 题原题，抢占式，数值越大优先级越高）**：

| 进程 | 到达 | 服务 | 优先级 |
|---|---|---|---|
| P1 | 0 | 60 | 1 |
| P2 | 20 | 42 | 2 |
| P3 | 30 | 13 | 3 |

推演：
- t=0 只有 P1 → 跑 0-20；
- t=20 P2 到达，优先级 2 > 1 → **抢占**，P2 跑 20-30（已干 10，还剩 32）；
- t=30 P3 到达，优先级 3 最高 → 抢占，P3 跑 30-43 结束；
- t=43 剩下 P2(剩 32，prio 2)、P1(剩 40，prio 1) → P2 跑 43-75 结束；
- t=75 P1 跑 75-115 结束。

甘特图：`P1[0-20] | P2[20-30] | P3[30-43] | P2[43-75] | P1[75-115]`

| 进程 | 到达 | 服务 | 完成 | 周转 T | 带权 W | 等待 |
|---|---|---|---|---|---|---|
| P1 | 0 | 60 | 115 | 115 | 1.917 | 55 |
| P2 | 20 | 42 | 75 | 55 | 1.310 | 13 |
| P3 | 30 | 13 | 43 | 13 | 1.000 | 0 |

平均周转 = 183/3 = **61**（与老师口算一致）；平均带权 = 4.226/3 ≈ **1.41**；平均等待 = 68/3 ≈ **22.67**。

#### 6. RR 时间片轮转

规则：就绪进程按 FCFS 排队，每个进程最多连续运行一个**时间片 q**；q 用完（时钟中断）就强制剥夺、排到队尾。**抢占式（由时钟中断驱动）**，只适用于**低级调度**。

**算例**（教材补充，q = 2）：

| 进程 | 到达 | 服务 |
|---|---|---|
| P1 | 0 | 5 |
| P2 | 1 | 4 |
| P3 | 2 | 2 |

推演（每次时间片结束把当前进程挂到队尾）：
- 0-2 P1（剩 3），此时就绪队列：P2(1 到)、P3(2 到)，P1 排到队尾 → 队列 P2, P3, P1；
- 2-4 P2（剩 2）→ 队列 P3, P1, P2；
- 4-6 P3 跑完（2 个）→ 队列 P1, P2；
- 6-8 P1（剩 1）→ 队列 P2, P1；
- 8-10 P2 跑完 → 队列 P1；
- 10-11 P1 跑完。

甘特图：`P1[0-2] | P2[2-4] | P3[4-6] | P1[6-8] | P2[8-10] | P1[10-11]`

| 进程 | 到达 | 服务 | 完成 | T | W | 等待 |
|---|---|---|---|---|---|---|
| P1 | 0 | 5 | 11 | 11 | 2.20 | 6 |
| P2 | 1 | 4 | 10 | 9 | 2.25 | 5 |
| P3 | 2 | 2 | 6 | 4 | 2.00 | 2 |

平均周转 = 24/3 = **8.0**；平均带权 = 6.45/3 = **2.15**；平均等待 = 13/3 ≈ **4.33**。

- q 极大 → 退化成 FCFS；q 极小 → 切换开销占比过高（q 应略大于一次上下文切换时间，且让 80% 以上的进程在一个时间片内完成）。

#### 7. 多级反馈队列 MLFQ（教材补充，课上仅点名"先跳过"）

规则（做题需先确认题目给的规则，通常为）：
1. 设 n 个队列 Q1…Qn，**优先级 Q1 最高**，时间片依次加倍（q, 2q, 4q…），最后一级用 FCFS/RR；
2. 新进程一律进入 **Q1** 队尾；
3. 在 Qk 中用完时间片仍未完成 → **降入 Q(k+1) 队尾**；
4. **只有高优先级队列为空时**才调度低优先级队列；有新进程进入高优先级队列可**抢占**当前进程。

**算例**（q1 = 1，q2 = 2，Q3 为 FCFS）：

| 进程 | 到达 | 服务 |
|---|---|---|
| P1 | 0 | 6 |
| P2 | 1 | 2 |
| P3 | 5 | 1 |

推演：
- t=0 P1 进 Q1，跑 0-1（剩 5）→ 降入 Q2；
- t=1 P2 进 Q1（更高队列），抢占 → P2 跑 1-2（剩 1）→ 降入 Q2；
- t=2 Q1 空，Q2 中 P1(5) 在前 → P1 跑 2-4（用满 2，剩 3）→ 降入 Q3；
- t=4 Q2 中 P2(1) → 跑 4-5 结束；
- t=5 P3 进 Q1 → 跑 5-6 结束（**后到的短作业立刻得到响应**）；
- t=6 Q1、Q2 空，Q3 中 P1(剩 3) → 跑 6-9 结束。

甘特图：`P1[0-1] | P2[1-2] | P1[2-4] | P2[4-5] | P3[5-6] | P1[6-9]`

| 进程 | 到达 | 服务 | 完成 | T | W | 等待 |
|---|---|---|---|---|---|---|
| P1 | 0 | 6 | 9 | 9 | 1.50 | 3 |
| P2 | 1 | 2 | 5 | 4 | 2.00 | 2 |
| P3 | 5 | 1 | 6 | 1 | 1.00 | 0 |

平均周转 = 14/3 ≈ **4.67**；平均带权 = 4.5/3 = **1.50**；平均等待 = 5/3 ≈ **1.67**。

#### 8. 调度算法总表（抢占性 / 饥饿 / 场景）

| 算法 | 抢占性 | 饥饿风险 | 优点 | 缺点 | 适用场景 |
|---|---|---|---|---|---|
| FCFS | **非抢占** | **无**（严格按到达顺序，人人有份） | 简单、公平、开销小 | 护航效应，短作业/ I/O 型被长作业拖死，平均周转差 | 批处理系统、作业调度 |
| SJF | 默认非抢占，**也可抢占** | **有**（长作业可能永远等不到） | **平均周转/平均等待理论最短** | 需预知运行时间（难），对长作业不利 | 批处理、作业可预估时长 |
| SRTF | **抢占** | **有**（长作业被不断插队） | 平均等待时间最短，响应好 | 切换频繁、开销大，需记录剩余时间 | 分时、交互式 |
| HRRN | 非抢占 | **无**（等得越久响应比越高，必然轮到自己） | 兼顾等待时间与长短作业，无饥饿 | 每次调度都要算所有进程的 R，开销大 | 批处理 |
| 优先级 | **两种都有** | **有**（低优先级饿死；动态优先级可缓解） | 灵活体现紧迫程度，可支持实时 | 静态优先级易饥饿；优先级反转问题 | 实时系统、分时系统 |
| RR | **抢占**（时钟中断） | **无**（每个进程都能轮到） | 响应快、公平，适合交互 | q 太小→开销大；q 太大→退化为 FCFS；平均周转不一定好 | 分时/交互式系统 |
| 多级队列 | 一般抢占 | 有（队列间固定优先级） | 不同类型进程用不同策略 | 进程类型固定、不够灵活 | 通用 OS |
| 多级反馈队列 | **抢占** | **有**（长作业不断降级，可能饿死） | 无需预知运行时间，兼顾响应与短作业，最通用 | 实现复杂、参数多 | 通用 OS（UNIX/Windows 思想） |

> 判断饥饿的口诀：**能"插队"的会饿**（SJF/SRTF、优先级、MLFQ 中长作业被降级）；**按顺序排队或等待会提升优先级的不会饿**（FCFS、HRRN、RR）。

3. **线程共享/私有**：2011 年考栈指针，2024 年又考文件描述符，老师明确说"这种题 11 年考了，24 年又提"，必须记牢。（选择）
4. **用户级线程 vs 内核级线程**："真题出现过两次左右"，60、66 题反复考"谁创建 TCB、谁切换效率高"。（选择）
5. **判断哪些算法会饥饿**（课后 43 题）：SJF、优先级会饥饿，FCFS、HRRN、RR 不会。（选择）

7. **周转时间 = 完成 − 提交，带权周转 = 周转 ÷ 运行时间**："考试中让你算的最多的就是周转时间和带权周转时间"。（大题/选择）
8. **抢占式优先级调度要审"数值大还是小代表优先级高"**（53 题原话："408 一定要细心一点"）。（选择）

## 快速技巧与口诀

1. **状态判定三步**：先问"它有没有 CPU"→ 有 CPU 才可能"主动阻塞"；再问"它缺什么"→ 只缺 CPU 是就绪，缺事件是阻塞；最后问"谁动的"→ 自己动=主动（运行→阻塞），别人动=被动（阻塞→就绪）。
2. **不可能转换四连**：就绪不阻塞、阻塞不运行、创建不运行、挂起不运行。
3. **算周转四步模板**：① 画时间轴 ② 按规则填每段区间（抢占式要标"剩余时间"）③ 读每个进程的完成时刻 f ④ T=f−a，W=T/s，最后求平均。带权周转可以 >10，别以为算错。
4. **抢占式 SJF 的比较对象**是"新到进程的服务时间"与"当前进程的**剩余**时间"，不是原始服务时间。
5. **RR 推演技巧**：每次时间片结束时，先把"这一段时间内新到达的进程"按到达顺序入队，再把"刚被剥夺的进程"挂到队尾。
6. **MLFQ 推演技巧**：先写清三条规则（新进程入 Q1、用完时间片降级、高队列非空不跑低队列），每换一个队列就标一次剩余时间。
7. **线程私有记"一栈两器三 ID"**：栈（栈指针）、PC + 通用寄存器、线程 ID/状态；**堆和文件描述符都是共享的**。
8. **优先级设置常识**：交互型 > 非交互型，I/O 型 > 计算型（让慢设备尽早启动）。

## 易错点与坑

1. **就绪态不能直接变阻塞态**。就绪进程没有 CPU，无法发起 I/O；"就绪→阻塞"是错误选项的高频设置。
2. **阻塞态进程即使 CPU 空闲也不能运行**，必须先被唤醒进入就绪队列。选项里"CPU 空闲时阻塞进程立即执行"必错。
3. **阻塞 ≠ 终止**：阻塞只是暂时让出 CPU，PCB 仍在，事件完成即唤醒。
4. **线程私有"栈"、共享"堆"**。2011 年真题问"线程不能共享什么"，答案就是栈指针；不要把"栈"和"堆"混为一谈。
5. **文件描述符属于进程**，同一进程内一个线程 open 得到的 fd，其他线程可直接使用（2024 年真题）。
6. **父进程与子进程不共享虚拟地址空间**：各自从 0 开始编址，是**独立**的虚拟地址空间；fork 后共享的是部分**物理页**（写时复制），不是虚拟地址空间。67 题 B 选项即错在此。
7. **用户级线程的致命缺点**：一个线程因 I/O 阻塞会让**整个进程**阻塞；且不能利用多核。内核级线程才没有这个问题。
8. **时间片 q 的两难**：q 过大 → 退化为 FCFS，响应变差；q 过小 → 上下文切换开销占比过高。不能说"q 越小越好"。
9. **优先级方向**：题目说"数值越大优先级越高"和"越小越高"都常见，53 题就是数值大的优先；不看清方向整题全错。
10. **等待时间是多段之和，响应时间只算第一次**。两者只有"进程只被调度一次"时才相等。
11. **带权周转时间的分母是服务时间，不是周转时间**；平均带权周转 ≠ 平均周转 ÷ 平均服务。
12. **FCFS 是唯一的"绝对无饥饿"算法之一**，但它的平均周转时间并不最优；不要因为"公平"就选它"效率最高"。
13. **闲逛进程不占 CPU 以外的资源、永不阻塞、优先级最低**，不是普通用户进程。

## 本章例题

### 例 1（课后 56 页 61 题·概念）
进程正在读磁盘，分别说明 I/O 开始与 I/O 完成时的状态变化。
**解**：磁盘、打印机、键盘、鼠标、显卡、网卡都属于 I/O 设备（磁盘属外存）。① I/O 开始 → 进程**运行态 → 阻塞态**（主动让出 CPU，否则占着 CPU 干等）；② I/O 完成 → 中断处理程序把它**阻塞态 → 就绪态**（唤醒），插入就绪队列等下次调度。
**答案**：开始→阻塞；完成→唤醒为就绪。

### 例 2（63 题·概念）
下列哪个事件会使进程从**运行态变为就绪态**？
**解**：申请内存失败 → 资源不足 → **阻塞**；启动 I/O 设备 → **阻塞**；P 操作（申请信号量失败）→ **阻塞**；被更高优先级进程抢占 → **就绪**。
**答案**：被更高优先级进程抢占。

### 例 3（64、65 题·概念）
① 什么情况引起**运行→阻塞**？② 什么情况引起**唤醒（阻塞→就绪）**？
**解**：① 申请已被占用的临界资源（如打印机被别的进程占着）、读磁盘（I/O 开始）、P 操作；② I/O 操作结束、某进程退出临界区释放了资源、V 操作。
**答案**：① 申请临界资源失败/启动 I/O/P 操作；② I/O 完成、退出临界区、V 操作。

### 例 4（69 题·概念）
下列不会引起**运行态→阻塞态**的是：A 读文件 B 申请外部设备 C 时间片用完 D P 操作。
**解**：读文件要访问磁盘（外存）→ I/O → 阻塞；申请打印机可能申请不到 → 阻塞；P 操作可能失败 → 阻塞；**时间片用完是运行→就绪**。
**答案**：C。

### 例 5（71 题·概念）
关于线程与状态转换，哪个是"运行态→就绪态"？
**解**：键盘输入、缺页（数据不在内存、要去磁盘取）都属于 I/O 等待 → 阻塞；只有**主动让出 CPU** 才是运行→就绪。
**答案**：主动让出 CPU（yield）。

### 例 6（60 题·线程）
判断：① 进程是资源分配的基本单位 ② 线程是资源分配的基本单位 ③ 系统级线程和用户级线程都需要内核支持 ④ 同一进程各线程共享进程地址空间。
**解**：① 对。② 错——线程共享进程资源，线程是**调度**的基本单位。③ 错——**用户级线程的创建/撤销/切换全在用户态由线程库完成，不需要内核支持**，只有内核级（系统级）线程才需要。④ 对。
**答案**：②③ 错。

### 例 7（66 题·线程）
判断：A 内核级线程由操作系统完成 B 操作系统为用户级线程创建 TCB C 用户级线程切换比内核级效率高 D 用户级线程不需要操作系统参与。
**解**：B 错在"字眼没对上"——**操作系统只为内核级线程创建 TCB**，用户级线程的 TCB 由用户空间的线程库维护。C 对：内核级线程切换要从用户态陷入内核态（经中断等），开销更大；用户级线程切换全在用户态。D 对。
**答案**：B。

### 例 8（59、73 题·线程共享）
① 同一进程的多个线程，不能共享的是？② 进程 P 中线程 T 打开 test.docx 得到文件描述符 fd=3，之后创建线程 Ta、Tb，Ta、Tb 能共享什么？
**解**：① 每个线程有**独立的栈和栈指针**，不能共享；代码段、全局变量、打开的文件都可共享。② fd 是进程级资源（登记在 PCB 的文件描述符表中），Ta、Tb **可共享该 fd、可共享进程地址空间**；**栈不可共享**。
**答案**：① 栈指针；② 地址空间 + 文件描述符，不含栈。

### 例 9（67 题·进程）
关于父进程与子进程，判断：A 可并发执行 B 共享虚拟地址空间 C 各有自己的 PCB D 不能同时使用同一临界资源。
**解**：A 对，父子都是独立进程可并发。B **错**——每个进程有独立虚拟地址空间（都从 0 开始编址），fork 后只是部分物理页面按写时复制共享，虚拟地址空间并不共享。C 对，有进程就有 PCB。D 对，临界资源同一时刻只允许一个进程使用，亲缘关系也不例外。
**答案**：B 错。

### 例 10（课后 53 题·计算，抢占式优先级）
三个进程 P1(0,60,优先级 1)、P2(20,42,优先级 2)、P3(30,13,优先级 3)，数值越大优先级越高，求平均周转时间。
**解**：
① 画甘特图：`P1[0-20] | P2[20-30] | P3[30-43] | P2[43-75] | P1[75-115]`
② 完成时刻：P1=115、P2=75、P3=43。
③ 周转：P1=115−0=115；P2=75−20=55；P3=43−30=13。
④ 平均 = (115+55+13)/3 = 183/3 = **61**。
**答案**：平均周转时间 61（平均带权约 1.41）。

### 例 11（课后 43 题·饥饿）
哪些调度算法可能产生饥饿？
**解**：SJF/SRTF（长作业被不断插队）、优先级（低优先级饿死）、多级反馈队列（长作业不断降级）会饥饿；FCFS（按到达顺序，人人有份）、HRRN（等得越久响应比越高）、RR（轮流，每人都能拿到时间片）不会。
**答案**：SJF、优先级、MLFQ。
