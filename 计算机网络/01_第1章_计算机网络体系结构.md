## 知识点详解

### 一、1.1.1 三种交换方式

#### 1. 电路交换（Circuit Switching）

**三阶段**：建立连接 → 传输数据 → 释放连接。建立连接时先确定一条**专用物理通路**，这条通路**独占**——A、B 用它传数据期间，其他设备不能用。传完必须**释放连接**。

**特点（背"直达"二字）**：
- 数据按序到达：12345 严格按发送顺序走同一条路，像队列先进先出，**不会失序**。
- **直达**：中间节点不做"收下来—检查—再发出"的存储转发，比特流直接穿过中间设备，**不引入额外转发时延**。
- 中间节点**不具备存储和差错检测能力**（差错只能在终点发现）；任一节点故障都必须**重新建立连接**；线路**独占**导致利用率低。

**优点**：时延小且稳定、实时性强、有序、无首部开销、控制简单。
**缺点**：建立连接时间长；独占使信道利用率低；不灵活（故障需重建）；无差错校验。

#### 2. 报文交换（Message Switching）

整个报文**一次**发送，报文上附加**源地址和目的地址**（老师比喻：寄快递必写寄件人、收件人）。

**核心机制 = 存储转发**：每个中间节点先把整个报文**完整接收下来**（相当于先"下载"），检查有无出错，再**重新发送**出去（相当于再"上传"）。这一收一发就是额外时延的来源。

- **无需建立连接**，随时可发；每个节点根据当前网络状况（拥塞情况）**自行选择当前最优链路**，某条路故障可自动改走别的路。
- **可进行差错校验**：中间节点收到就检查，出错就地丢弃，不必等传到终点。
- **缺点**：存储转发带来时延；**缓存开销大**（传 1 GB 电影，中间设备要能存下整个报文）；报文太长，一出错整个重传。

#### 3. 分组交换（Packet Switching）

同样基于**存储转发**，但先把长报文**切分为等长小分组**（如 1000 B 切成每 200 B 一组共 5 组）。**每个分组都独立加上首部**：源地址、目的地址、**分组编号**（五份分开寄，每份都要写收发地址，还要编号，接收方才能重排）。

**优点**：
1. 分组短，**转发时延小**，且能像**流水线**一样让各节点并行工作（下节的 (N+k−1)T 就是它）。
2. 分组**定长**，节点**缓存区大小可预先分配**，开销小。
3. 出错**只重传出错的那一组**（1000 B 中 200 B 错，只重发 200 B），重传量小。
4. 逐跳动态选路，线路利用率高。

**缺点**：每分组都要首部，**额外开销**（有效数据占比下降）；分组各自选路可能**失序或重复**，接收方需按编号重组。

#### 4. 三种方式对比（老师要求"只判断、不背诵"）

| 对比项 | 电路交换 | 报文交换 | 分组交换 |
|---|---|---|---|
| 是否需建立连接 | 需要（三阶段） | 不需要 | 不需要 |
| 传输单位 | 比特流 | 整个报文 | 分组（首部+数据段） |
| 中间节点 | 直达，不存储转发 | 存储转发 | 存储转发 |
| 路由选择 | 连接建立时一次选定 | 逐跳动态选路 | 逐跳动态选路 |
| 是否有序到达 | **有序** | **有序** | **可能失序/重复** |
| 差错校验 | 端到端，中间不检 | 中间节点可检 | 中间节点可检 |
| 缓存开销 | 无 | 最大（整报文） | 小（定长可预算） |
| 出错重传量 | 全部 | 整个报文 | 仅出错分组 |
| 线路利用率 | 低（独占） | 较高 | 高 |
| **完成传输时间** | **最少** | **最多** | **居中** |
| 典型场景 | 电话网 | 电报 | 计算机网络（Internet） |

**结论（第 15 页表格，可直接秒选）**：完成传输时间 **电路交换 < 分组交换 < 报文交换**；是否乱序只有**分组交换**会乱序。

#### 5. 时延计算通用模型（本章命脉）

符号：`L` 报文/分组长度（bit）、`C` 链路发送速率（b/s）、`N` 分组数、`k` 链路段数（路由器数 = k−1）、`D` 链路长度、`V` 电磁波传播速率。

单跳**发送时延**：

```
T = L / C      （一个设备把一个分组全部推上链路所需时间）
```

**三种交换的总时延**（忽略处理、排队时延；传播时延另加 k·t_p）：

| 方式 | 总时延公式 | 为什么 |
|---|---|---|
| 电路交换 | `t_建立 + L/C` | 建立后**直达**，只有源端发一次，中间**不计转发** |
| 报文交换 | `k × (L报文 / C)` | 整个报文要走 k 段，每段都要完整收下再发出 = k 次发送时延 |
| 分组交换 | `(N + k − 1) × T` | N 个分组串行从源端发出花 NT；最后一个分组还要再经 (k−1) 个节点转发，每个 T |

**(N+k−1)T 的推导（"后面推着前面走"）**：源端必须把 N 个分组全部发完，耗时 N·T；此时最后一个分组才刚上第一段链路，它还要经过 k−1 个路由器各转发一次，每次 T，故再加 (k−1)T。前面 N−1 个分组早已被"推"到终点，不用另算。三个分组、两个路由器时：(3+3−1)×T = 5T。

**流水线直观图**（3 分组、2 路由器、忽略传播）：

```
时间轴 →   T     2T     3T     4T     5T
H1      [1]    [2]    [3]
R1             [1]    [2]    [3]
R2                    [1]    [2]    [3]   ← 5T 完成
```

**算例 A（三种方式同题硬算，25 年真题数据）**：H1—R1—R2—H2，三段速率依次 10 / 100 / 1000 Mb/s，数据 2 MB = 2×10⁶ B，分组长度 400 B，电路建立时间 32 μs，忽略传播时延与首部开销。

- 电路交换：`32 μs + 2×10⁶×8 /(10×10⁶) = 32 μs + 1.6 s = 1.600032 s`
- 报文交换：整报文逐段转发 `1.6 + 0.16 + 0.016 = 1.776 s`
  （0.16 = 16×10⁶/100×10⁶，0.016 = 16×10⁶/1000×10⁶）
- 分组交换：`N = 2×10⁶/400 = 5000`，`T = 400×8/(10×10⁶) = 0.32 ms`
  `5000×0.32 ms = 1600 ms`；末分组过 R1：`400×8/(100×10⁶) = 32 μs`；过 R2：`3.2 μs`
  总 = `1600 + 0.032 + 0.0032 = 1600.0352 ms ≈ 1.6000352 s`

排序：**1.600032 s（电路） < 1.6000352 s（分组） < 1.776 s（报文）**，与表格结论一致。注意电路只比分组快 3.2 μs——这题必须硬算，不能凭感觉。

### 二、1.1.2 性能指标

#### 1. 速率（数据率 / 比特率）

定义：单位时间传送的**比特数**，单位 b/s（bit per second）。注意是**比特**不是字节。

**K、M、G 的换算（高频陷阱）**：

| 场景 | 进制 | 1K / 1M / 1G |
|---|---|---|
| **速率、频率**（网速、时钟频率、带宽 b/s） | 十进制 | 10³ / 10⁶ / 10⁹ |
| **存储容量**（文件大小、内存、页面大小、缓存） | 二进制 | 2¹⁰ / 2²⁰ / 2³⁰ |

判据：看到"每秒""赫兹""带宽"→ 十进制；看到"字节""容量""4 KB 页面"→ 二进制。**题目明确指定时以题目为准**（题 14、15 都专门注明"兆用 10⁶"）。书写规范：大写 **K = 2¹⁰**，小写 **k = 10³**，其余 M、G 均大写，只能靠场景判断。

#### 2. 带宽（Bandwidth）

两种含义，看单位：
- 单位 **b/s**：链路**理论上最高**的数据传输速率（"装 1000 兆宽带"即此意，实际达不到）。
- 单位 **Hz**：信号的**频带宽度**（频率范围），用于 2.1 小节奈奎斯特 / 香农公式。

#### 3. 吞吐量（Throughput）

定义：单位时间内**实际通过**某个网络（或接口、信道）的数据量，单位 b/s。带宽是"理论上限"，吞吐量是"实际成绩"，受带宽、负载、协议开销共同限制，故 **吞吐量 ≤ 带宽**。

#### 4. 时延（Delay / Latency）

`总时延 = 发送时延 + 传播时延 + 处理时延 + 排队时延`（经过多个节点时逐节点累加）

| 时延 | 定义 | 公式 | 由什么决定 |
|---|---|---|---|
| **发送时延**（传输时延） | 主机/路由器把分组的**全部比特推上链路**所需时间 | `t_s = L(bit) / C(b/s)` | **分组长度 + 带宽**，与距离无关 |
| **传播时延** | 比特在**信道中从一端传到另一端**所需时间 | `t_p = D(m) / V(m/s)` | **距离 + 介质（传播速率）**，与带宽无关 |
| **处理时延** | 节点收下后**解析首部、查表选路、差错检验**的时间 | 题目给定，不可自算 | 节点性能 |
| **排队时延** | 分组在节点**缓存队列中等待**处理/转发的时间 | 题目给定，不可自算 | 网络负载 |

老师的分界：**发送时延 = "从设备里把它发出去"（把数据推上网络）；传播时延 = "从链路一端跑到另一端"（在网络上跨城市传输）**。

- 关键区分：**发送时延由带宽决定，传播时延由距离和介质决定**。传 1 MB 和 1 GB 的耗时差是发送时延；北京→上海与上海→苏州的耗时差是传播时延。
- 日常感受：传大文件要等几分钟（发送时延主导）；聊天消息"秒回"（传播时延极短，通常可忽略）。
- 真题主流只考**发送 + 传播**；处理、排队时延"了解即可"，**题干不给就不算**。

**算例 B（老师课上的 1000 B 例子）**：分组 1000 B，A 以 100 Mb/s 发出，路由器以 80 Mb/s 转发，忽略传播/处理/排队。
`t_s(A) = 1000×8/(100×10⁶) = 8×10⁻⁵ s = 0.08 ms`；`t_s(R) = 1000×8/(80×10⁶) = 1×10⁻⁴ s = 0.1 ms`；总 = 0.18 ms（老师口播"0.8 加 0.01"为口误，按算式为 0.08 + 0.1）。

**为什么"卫星链路带宽再大，RTT 也不会小"**（老师反复强调的一句话的推论）：RTT 的主体是**往返传播时延** `2D/V`。同步卫星高度约 3.6×10⁴ km，电磁波 V ≈ 2×10⁸ m/s（教材补充），单程 `3.6×10⁷/2×10⁸ = 0.18 s`，往返约 **270 ms**（含地面段更长）。带宽只出现在分母的**发送时延**里：把带宽从 1 Mb/s 提到 1 Gb/s，`L/C` 缩小 1000 倍，但 `2D/V` 一毫秒都不变。所以卫星上网"带宽够但卡"是物理距离决定的，加钱升带宽救不了。

#### 5. 时延带宽积（Bandwidth-Delay Product）

```
时延带宽积 = 传播时延 × 带宽 = t_p × C   （单位：比特）
```

**含义：链路上"正在飞行"的比特数**，即这条链路能容纳多少个比特（老师用"横截面积（带宽）× 长度（传播时延）= 体积"作类比）。

推导（老师原话思路）：A 以速率 C 不停发送，第一个比特经过 `t_p` 到达接收端，这 `t_p` 期间 A 一共发出了 `C×t_p` 个比特，全都铺在链路上——所以它同时等于"发送端在传播时延内发出的数据量"和"信道中容纳的比特数"。

**算例 C**：速率 10 Mb/s、传播时延 0.5 s → 时延带宽积 = `10×10⁶ × 0.5 = 5×10⁶ bit = 5 Mbit`，即这条"管道"里同时装着 5 Mbit 数据。

**必须记住的两个不要混**：
- `传播时延 × 带宽` = **链路上的比特数**（时延带宽积）
- `发送时延 × 带宽` = **发送端在这段时间内发出的数据量** = 报文长度（等于 `t_s × C = L`，恒等，没有信息量）

#### 6. 往返时延 RTT（Round-Trip Time）

定义：从发送端**发出**一个分组开始，到收到接收端**返回的确认**为止的总时间。

组成：`RTT = 往返传播时延 + 中间节点的处理/排队时延 + 确认分组的发送时延`（数据分组的发送时延是否计入，看题目口径）。

**注意**：RTT 不只是 `2×传播时延`，路径上每个路由器都会叠加处理和排队时延。

#### 7. 利用率（Utilization）

老师明确：**信道利用率放在 3.4 小节讲，本节不看**。这里只给结论性定义（教材补充）：

- 信道利用率 `U = 有效发送数据的时间 / 总时间`。停止-等待协议下 `U = (L/C) / (L/C + RTT + L'/C)`，L 为数据帧长、L' 为确认帧长。
- 利用率不是越高越好：利用率升高 → 排队时延急剧增大（网络"堵车"），故有时延随利用率上升而陡增的结论。

### 三、1.2.1 分层、协议、服务、接口

#### 1. PDU / SDU / PCI

- **SDU（服务数据单元）**：上层交给本层、要求本层传输的数据（相邻层之间交换的数据单位）。
- **PCI（协议控制信息）**：本层加上的控制信息（首部，链路层还加尾部）。
- **PDU（协议数据单元）**：本层对等层之间传送的数据单位。

**核心等式**：

```
第 N 层 PDU = 第 N 层 SDU + 第 N 层 PCI
第 N+1 层 PDU  =  第 N 层 SDU
```

即：上层整个 PDU 落到下层就变成本层的 SDU，本层再加上自己的 PCI 封装成本层 PDU，逐层"套娃"（老师比喻：寄贵重快递，一层层包装；收方一层层拆）。

**特殊点：链路层既加头又加尾**（尾部放帧检验序列 FCS），其余各层只加头。

#### 2. 协议（Protocol）

定义：为进行网络中数据交换而建立的**规则、标准或约定**，是**对等层之间**的通信规则。

**三要素**：
- **语法**：数据与控制信息的**格式**（首部有哪些字段、各占几字节）。
- **语义**：各字段/控制信息的**含义**，即要发出何种控制信息、完成何种动作、做出何种应答。
- **同步（时序）**：事件实现的**顺序**（如 TCP 三次握手的先后次序）。

老师提示：这三个词学完 5.2 的 TCP 再回看最清楚，第一轮先记名词。

#### 3. 服务（Service）与接口（SAP）

- **服务**：**下层向上层**提供的功能调用，本层只能"使用"下层的服务，看不到下层怎么实现。
- **接口（服务访问点 SAP）**：相邻两层交换信息的逻辑点，上层通过 SAP 使用下层的服务。
- **协议是水平的，服务是垂直的**（老师原话"协议是水平的"）：

| 对比 | 协议 | 服务 |
|---|---|---|
| 方向 | **水平**：不同系统的**对等层**之间 | **垂直**：同一系统内**相邻层**之间 |
| 内容 | 怎么通信（规则、格式、顺序） | 能提供什么能力 |
| 可见性 | 对上层**透明**（上层看不见本层协议） | 上层直接用，通过 SAP |
| 关系 | 协议的实现**支撑**服务 | 服务由下层协议+下层服务共同完成 |

一句话：**服务是"能干什么"，协议是"怎么干成的"；换协议不影响服务（服务不变），改服务才影响上层。**

### 四、1.2.2 OSI 七层模型

**七层顺序（必背，从下往上）**：物理层 → 数据链路层 → 网络层 → 传输层 → 会话层 → 表示层 → 应用层。

**各层职责与要素对照表**（设备与协议列为教材补充，老师课上只点了路由器、FTP/DNS/HTTP）：

| 层 | 主要职责 | 传输单位（PDU） | 典型设备 | 典型协议 |
|---|---|---|---|---|
| 7 应用层 | 为用户应用进程提供网络服务：文件传输、邮件、网页浏览 | 报文 | 主机（网关） | HTTP、FTP、SMTP、DNS、TELNET |
| 6 表示层 | 数据**编码、压缩、加密解密**，格式转换 | 报文 | 主机 | JPEG、ASCII、加密算法 |
| 5 会话层 | **建立、维护、终止会话**；同步机制、检查点、断点续传 | 报文 | 主机 | RPC、会话管理 |
| 4 传输层 | **进程到进程（端到端）**通信，复用/分用、可靠传输、流量控制 | 报文段（TCP）/ 用户数据报（UDP） | 主机 | TCP、UDP |
| 3 网络层 | **源主机到目的主机**的传输、路由选择、分组转发、拥塞控制 | 分组 / 数据报 | **路由器**、三层交换机 | IP、ICMP、IGMP、ARP（教材补充） |
| 2 数据链路层 | **相邻节点**之间传输，成帧、差错控制、流量控制、介质访问 | 帧（加头又加尾） | 交换机、网桥、网卡 | HDLC、PPP、Ethernet、ARP（教材补充） |
| 1 物理层 | 在传输介质上透明传输**比特流**，规定接口机械/电气/功能/规程特性 | 比特（流） | 中继器、集线器 | RS-232、RJ-45（教材补充） |

**老师点明的三条边界**：
1. **路由器最多工作到网络层**。所以 A 机→B 机的真实路径是：A 从应用层逐层封装到物理层 → 路由器从物理层解到网络层、再封装回物理层 → B 逐层解包。用户感觉"QQ 直接发给对方 QQ"，实际是层层借下层之力。
2. **传输介质（双绞线、光缆）不属于物理层**，物理层只规定接口特性。
3. 每层"看到的单位"不同：物理层一次看一个比特，链路层一次看一个帧（帧里含很多字节）。

**各层的"地址/范围"记忆链（老师强调的分工）**：
- 链路层：只管**下一跳**（相邻节点），依据 **MAC 地址**，"我只管下一步发给 R1，最终给谁不管"。
- 网络层：只管**哪两台主机**（A→B），依据 **IP 地址**，不管哪个软件。
- 传输层：只管**哪两个进程**（QQ↔QQ），依据**端口号**（同一软件在不同主机上端口号可以不同）。
- 会话层：一切与"会话"有关的词都是它——同步机制、断点续传、恢复会话、检查点。

### 五、1.2.3 TCP/IP 四层与五层模型

| OSI 七层 | TCP/IP 四层 | 五层（教学模型） |
|---|---|---|
| 应用层 + 表示层 + 会话层 | **应用层** | 应用层 |
| 传输层 | 传输层 | 传输层 |
| 网络层 | **网际层**（IP 层） | 网络层 |
| 数据链路层 + 物理层 | **网络接口层**（链路层） | 数据链路层 / 物理层（分列两层） |

**要点**：
- TCP/IP 的**网际层**就是 OSI 的**网络层**，只是换名；其**应用层**把 OSI 的会话、表示、应用三层合并。
- **标准只有两种划分：OSI 七层、TCP/IP 四层**。**五层不是标准**，只是多数教材为讲课方便把网络接口层拆成物理层+链路层。考"计网分为几层"，答七层或四层。
- 传输层两大协议：**TCP**（面向连接、可靠）、**UDP**（无连接、不可靠），详见第 5 章；应用层协议 FTP、DNS、HTTP 详见第 6 章。

### 六、连接方式与交付方式（后续章节反复用）

**面向连接 vs 无连接**：

| 对比 | 面向连接 | 无连接 |
|---|---|---|
| 是否事先建链 | 必须先建立连接，传完释放 | 直接发，无需建立 |
| 顺序/可靠性 | 通常可靠、有序 | 通常不可靠、可能失序 |
| 典型代表 | **TCP**、电路交换 | **IP、UDP**、报文/分组交换 |
| 开销 | 建链/释放开销，首部大 | 开销小，时延小 |

**可靠交付 vs 不可靠交付**：

- **可靠服务**：具备**检错、纠错、应答（确认）机制**，能保证数据**正确、完整、有序**地送达目的地。
- **不可靠服务**：只尽力而为（best effort），出错丢弃不负责重传，可靠性交给上层。
- **有应答 / 无应答**：接收方收到数据后向发送方回一个**确认（ACK）**称有应答；不回则无应答。

**"可靠" ≠ "面向连接"**：面向连接是"有没有建链"，可靠是"有没有检错/纠错/确认"，二者是两条独立坐标，考试常拿 TCP（既面向连接又可靠）与 UDP（既无连接又不可靠）当唯一对照，容易形成错误绑定。

## 快速技巧与口诀

1. **流水线万能式**：`总时延 = (N + k − 1) × T`（T 为单跳发送时延，k 为链路段数 = 路由器数 + 1）。记法："**先把 N 个全发出去，再让最后一个走完全程**"（后面推着前面走）。
2. **报文交换 = k × T_报文**：整报文逐段存储转发，几段就几次发送时延。
3. **电路交换 = 建立时间 + 1 个 T**：直达，中间转发时间一律不计。
4. **三问定式**：① 分几组（用**净荷**算）→ ② 单跳 T 是多少 → ③ 末分组还要走几跳。列式前先画甘特图，前两三道题必画，熟了直接列式。
5. **单位换算口诀**："**速率频率十进制，容量存储二进制；K 大写 2¹⁰，k 小写 10³；题目指定听题目**"。
6. **时延带宽积的物理像**："带宽是管子粗细，传播时延是管子长度，乘积是管子容积（比特）"。
7. **"看见会话层就找同步/断点续传/检查点"**；"看见压缩加密编码就找表示层"。
8. **"链路层看下一跳，网络层看两台机，传输层看两个进程"**——地址分别是 MAC / IP / 端口。
9. **结论秒选手法**：先按"电路 < 分组 < 报文"选，若两个选项接近（如 25 年真题电路 1.600032 s 与分组 1.6000352 s 只差 3.2 μs），必须硬算末分组的转发开销。

## 易错点与坑

1. **时延带宽积用错时延**：必须是**传播时延 × 带宽**。误用发送时延 × 带宽，结果恰好等于报文长度（恒等变形），毫无意义。
2. **分组数用错分母**：分组数 = 总数据量 ÷ **每分组净荷**（分组长度 − 首部）。题 13 中分组 1000 B、首部 20 B，净荷 980 B，98 万 B ÷ 980 B = 1000 组；若用 1000 B 去除会算成 980 组，全盘皆错。
3. **字节忘乘 8**：`L` 必须以 **bit** 代入。题 14 的字幕数值（8M÷10M = 0.8 s、10K÷10M = 1 ms）就是把字节当比特算的，正确应为 6.4 s 与 8 ms（比值不变，但绝对数值全错）。
4. **M/K 进制混用**：速率用 10⁶，容量用 2²⁰；题 15 的 1 MB 若按 2²⁰ 算分组数会得 1048 组而非 1000 组。**题干注明"兆用 10⁶"时一律听题干的**。
5. **给电路交换多算转发时延**：电路交换是**直通**，中间节点不存储转发，只需"建立时间 + 源端发送时间"；把 100 Mb/s、1000 Mb/s 那两段也算进去就错了（这是 25 年真题的最大坑）。
6. **无条件套 (N+k−1)T**：该式成立的前提是**各跳速率相同且无处理/排队停顿**。题 11 有 10 ms 处理时延且路由器一次只能处理一个分组，第二个分组要排队等，公式退化为 `T + N×处理 + T`；题 17 逐跳速率不同（10/100/1000 Mb/s），末分组两跳转发时间必须分别用各自带宽算（0.032 ms 与 0.0032 ms），不能用同一个 T。
7. **RTT 误算成 2×传播时延**：还要加中间节点的处理、排队时延和确认帧的发送时延。
8. **"分组交换有序"是错的**：分组各自选路，可能失序、重复，正是需要**分组编号**的原因；反过来"报文交换会乱序"也是错的。
9. **五层当成标准**：标准只有 OSI 七层与 TCP/IP 四层，五层是教材为教学拆分出来的。
10. **把传输介质归入物理层**：双绞线、光缆等**传输介质本身不属于物理层**，物理层只规定接口特性。
11. **"可靠 = 面向连接"**：可靠看有没有检错/纠错/应答，连接看有没有建链，两者独立。
12. **首部开销漏算**：分组交换每个分组都要加首部，有效数据率 = 净荷/分组总长 < 带宽，题目问"有效数据率"时要乘这个比例。

## 本章例题

### 例 1（题 13，分组交换基础型）

**题干要点**：链路速率 100 Mb/s，分组长度 1000 B（首部 20 B），待发数据 98 万 B，路径经 2 个路由器，**不考虑拆装时间与传播时延**，求 H1 开始发送到 H2 全部收完的时间。

**步骤**：
1. 净荷 = 1000 − 20 = 980 B；分组数 `N = 980000 / 980 = 1000`。
2. 单跳发送时延 `T = 1000×8 /(100×10⁶) = 8×10⁻⁵ s = 0.08 ms`（H1 发、R1 转发、R2 转发均为 0.08 ms，因分组等长、链路同速）。
3. k = 3 段链路 → `(N + k − 1) = 1002`。
4. 总时延 = `1002 × 0.08 = 80.16 ms`。

**答案：80.16 ms**（即 NT + 2T）。

### 例 2（题 14，报文交换 vs 分组交换）

**题干要点**：甲、乙经 1 个路由器相连，两段链路均 10 Mb/s；数据 8 Mbit，分组长度 10 kbit，**不考虑传播时延、不考虑分组头开销**，兆按 10⁶ 计。比较两种方式总时延。

**步骤**：
1. 报文交换（k = 2 段）：`T_报 = 8×10⁶ /(10×10⁶) = 0.8 s`，总 = `2 × 0.8 = 1.6 s`。
2. 分组交换：`N = 8×10⁶ /(10×10³) = 800` 组；`T = 10⁴/(10×10⁶) = 1 ms`；总 = `(800 + 1) × 1 ms = 801 ms`。
3. 比较：801 ms < 1600 ms，**分组交换省时**。原因是分组一发出，路由器就能开始转发，不必等 8 Mbit 全部到齐（流水线）。

**答案：报文交换 1600 ms，分组交换 801 ms，分组交换更快。**
（注：字幕口播"8 兆 B""10 KB"，但老师算式 8M÷10M = 0.8 s 只有按比特才成立，故按 8 Mbit / 10 kbit 还原；若真以字节计，两式同乘 8，结论不变。）

### 例 3（题 15，含传播时延）

**题干要点**：分组 1000 B，带宽 100 Mb/s，时延带宽积 1000 bit，数据 1 MB（按 10⁶），经 1 个路由器（k = 2）。求总时延。

**步骤**：
1. `N = 10⁶ / 1000 = 1000` 组。
2. `T = 1000×8 /(100×10⁶) = 0.08 ms`。
3. 由时延带宽积反求传播时延：`t_p = 1000 /(100×10⁶) = 10 μs = 0.01 ms`。
4. 总 = `N·T + t_p + T + t_p = 1000×0.08 + 0.01 + 0.08 + 0.01 = 80.1 ms`。
（结构：源发完 N 组 → 末组传播一段 → 路由器转发一次 → 再传播一段到 H2。）

**答案：80.1 ms。**

### 例 4（题 11，非真题·易错题，含处理与排队时延）

**题干要点**：A 经 1 个路由器向 B 发 2 个分组，分组 1000 B，速率 1 Mb/s，路由器**处理时延 10 ms/组**且同一时刻只能处理一个分组，不考虑传播时延。

**步骤**：
1. `T = 1000×8 / 10⁶ = 8 ms`。
2. 画时间轴：A 发 1 号 0–8 ms，发 2 号 8–16 ms；R 处理 1 号 8–18 ms；2 号 16 ms 已到但需排队，等 18 ms 才开始，处理 18–28 ms；R 转发 1 号 18–26 ms，转发 2 号 28–36 ms。
3. 总 = `8 + 10 + 10 + 8 = 36 ms`（误选 34 ms 的错法：2T + 10 + T，漏掉了排队 2 ms）。

**答案：36 ms。**
**推广（N 个分组，含处理时延）**：`总 = T + N×t_处理 + T`；N = 3 时 = 8 + 30 + 8 = 46 ms。**关键：只要有排队停顿，(N+k−1)T 就失效，必须画图。**

### 例 5（题 17，2025 年真题，三种方式硬算）

**题干要点**：H1→R1 10 Mb/s、R1→R2 100 Mb/s、R2→H2 1000 Mb/s；数据 2 MB（10⁶ 计），分组 400 B，电路建立时间 32 μs，忽略传播时延与首部开销。比较 T_电路、T_分组、T_报文。

**步骤**：
1. 电路交换：`32 μs + 2×10⁶×8/(10×10⁶) = 32 μs + 1.6 s = 1.600032 s`（直达，R1、R2 不计转发）。
2. 报文交换：`16×10⁶/10×10⁶ + 16×10⁶/100×10⁶ + 16×10⁶/1000×10⁶ = 1.6 + 0.16 + 0.016 = 1.776 s`。
3. 分组交换：`N = 2×10⁶/400 = 5000`；`T = 400×8/(10×10⁶) = 0.32 ms`；
   `5000×0.32 ms = 1600 ms`（源端把 5000 组发完，与整报文发送时间相等，都是 1.6 s）；
   末组过 R1：`3200/(100×10⁶) = 32 μs`；过 R2：`3200/(1000×10⁶) = 3.2 μs`；
   总 = `1600 + 0.032 + 0.0032 = 1600.0352 ms ≈ 1.6000352 s`。
4. 排序：`T_电路(1.600032) < T_分组(1.6000352) < T_报文(1.776)`。

**答案：电路交换最短、报文交换最长，选 B。**
这题三个值极接近，必须在同一单位（秒/毫秒）下逐项相加，任何一步单位错乱都会选错。
