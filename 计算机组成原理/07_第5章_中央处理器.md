## 知识点详解

### 一、5.1 CPU 的功能和基本结构

#### 1. 功能

CPU 只有两件事：**执行指令**；**检测并响应各类异常与中断**。展开成六项基本功能：

1. **取指令并译码**：按 PC 取指、对操作码译码、**生成控制信号**（"控制信号"是 408 极重要的概念，学完 5.3 才真正懂）；
2. **更新 PC**：顺序执行自增，转移执行改写；
3. **算术逻辑运算**：由 ALU 完成；
4. **取操作数、写结果**：访问主存或 I/O 接口；
5. **处理异常与中断**：检测请求，必要时转处理程序；
6. **时序控制**：让所有指令按序推进。

#### 2. 结构与寄存器（高频概念题）

CPU 分为**运算器、寄存器、控制器、中断系统**四部分（另一常见划分是"运算器 + 控制器"两类，考题会问某硬件属于哪一类，须能对号入座）。

访问主存的标准路径：**地址送 MAR → 地址总线 → 控制总线发读/写命令 → 数据经数据总线送 MDR**。地址总线单向、数据总线双向、控制总线单向。

| 寄存器 | 作用 | 位数 |
|---|---|---|
| PC | 存放当前（下一条）指令的地址 | 由地址总线宽度 / 存储器容量决定 |
| IR | 暂存当前正在执行的指令 | = 指令字长 |
| MAR | 存放当前要访问的主存地址 | = 地址总线宽度 |
| MDR | 存放从主存读出、或将要写入主存的数据 | = 存储字长（≈数据总线宽度） |
| GPRs | 暂存操作数、中间结果或地址 | = 机器字长，编号占 log2n 位 |
| FR / PSW | 存放 ALU 运算产生的标志位（ZF、SF、OF、CF） | — |
| ID | 对 IR 中的操作码译码 | — |
| CU | 产生时序信号与控制信号 | — |

**PC 自增的增量**：不是"指令字节数"，而是**该指令所占的地址单元数**，取决于指令长度和编址方式；按字节编址时二者才一致（教材说"字节数"，老师指出这句不严谨）。

**可见 / 不可见**（考过两三次，选择、大题小问都考）：

- **可见**：通用寄存器、PC、标志寄存器 PSW（PSW 可见但**只读**，用户程序不能改写）；
- **不可见**：IR、MAR、MDR、页表基址寄存器；
- **移位寄存器**：不同架构说法不一，**真题出现过一次，按"不可见"记**。

> 记忆抓手：凡是"程序员能用指令直接读写"的才可见。IR/MAR/MDR 是 CPU 内部搬运工，指令里根本点不到它们。

#### 3. 机器字长 = ALU 位数 = 通用寄存器位数

机器字长反映运算能力，而 ALU 是真正干活的计算部件，ALU 的操作数又来自通用寄存器，故三者位数相同。真题问"哪个部件位数与机器字长相同"，答 **ALU 和通用寄存器**。

### 二、5.2 指令执行过程

#### 1. 指令周期与阶段划分

**指令周期**：从主存取出一条指令并执行完毕所需的全部时间。划分方式有三种：

- **两段**：取指周期 + 执行周期（最简，数据通路分析常用）；
- **三段**：取指 + 执行 + 中断；
- **五段**：IF 取指、ID 译码并读寄存器、EX 执行、MEM 访存、WB 写回（**流水线用这一套，必须记**）。

"机器周期"这个概念已淡化，做题基本只用**时钟周期**（第一章的最小时间单位）。

#### 2. 五阶段各自做什么

| 阶段 | 动作 | 备注 |
|---|---|---|
| IF | PC→MAR→主存→MDR→IR；PC 自增 | 有指令 Cache 时先查 Cache；任何指令都一样 |
| ID | 对 IR 中操作码译码，识别操作码与寻址方式；从寄存器读操作数 | 可能顺带做基址+偏移的地址计算、取立即数 |
| EX | 运算类：ALU 运算并产生标志位；访存类：算有效地址；转移类：算目标地址并判断是否转移 | 标志位送 FR |
| MEM | 读（load）或写（store）主存，可经 Cache | 运算类此阶段空 |
| WB | 结果写回寄存器 | 结果可来自 ALU，也可来自主存 |

"译码"和"读寄存器"是同一阶段的两件事，不要记混：译码针对**指令的操作码**，读寄存器针对**操作数**。

#### 3. 中断的位置

**一条指令执行完毕后才检测中断与异常**。检测到请求则保存断点（返回地址，通常为下一条指令或当前指令），PC ← 中断服务程序入口，执行完再返回（细节见 5.5）。

#### 4. 三种执行模型

| 模型 | CPI | 特点 |
|---|---|---|
| 单周期 | = 1 | 每条指令一个时钟；指令严格串行；**时钟周期取决于最慢的那条指令** |
| 多周期 | > 1（各指令不同） | 不同指令占不同时钟数；仍串行 |
| 流水线 | ≈ 1（理想 = 1） | 多条指令重叠，各处于不同阶段 |

#### 5. 指令与数据如何区分

二者都以二进制形式存放在存储器中，CPU 靠**指令周期的不同阶段**区分：**取指阶段取出的一定是指令，访存阶段取出的一定是数据**。这是冯·诺依曼结构"存储程序"的直接推论，选择题常考。

### 三、5.3 数据通路

#### 1. 定义与元件

**数据通路**：指令执行过程中数据经过的路径，以及路径上涉及的全部硬件（ALU、寄存器、暂存器、总线、MUX……），它描述"数据从哪出发、经过哪些部件、最后存到哪"，并由**控制部件产生的控制信号**控制。

| 类别 | 别名 | 特点 | 典型器件 |
|---|---|---|---|
| 组合逻辑元件 | 操作元件 | **内部不含记忆单元**，不存储结果 | 加法器、ALU、译码器、多路选择器、三态门 |
| 时序逻辑元件 | 状态元件 | **必含存储信息的记忆单元** | 各类寄存器、存储器 |

- **多路选择器 MUX**：多选一，由控制信号从多路输入中选一路输出；
- **译码器**：N 位输入 → 2^N 个输出，从中选中一个。用于操作码译码（3 位操作码 → 8 条指令）、地址译码；
- **三态门**：当开关用，EN=1 导通、EN=0 隔断，专门用来**避免总线冲突**；
- 图中**带箭头的虚线表示控制信号**（09 年真题例外，未用虚线）。

#### 2. 两种分类

- **按部件连接方式**：总线式（单总线、多总线）、专用数据通路；
- **按时序组织方式**：单周期、多周期、流水线。

**总线式**：把寄存器、ALU 等主要部件连接到一条或多条 **CPU 内部总线**上（注意区别于连接 CPU 与主存的**系统总线**）。

**单总线**：任何两个部件传数据都必须借道总线，不能直连。因此**同一时刻只允许一个部件向总线输出（out），但允许多个部件同时从总线接收（in）**。优点硬件简洁，缺点同一时刻只能传一组数据。

**专用数据通路**：部件之间点对点直连，不共用总线。优点无冲突，缺点布线复杂、扩展性差（加一个部件就要加一根线）。

> **单周期处理器不能采用单总线结构**——一个时钟只能做一次总线传输，光取指（PC→MAR、读主存、MDR→IR）就要好几个时钟，根本压不进一个周期。单周期 CPU 用的是专用数据通路。

#### 3. 单总线数据通路的关键细节

典型图（22 年真题原图）含：PC、MAR、MDR、IR、通用寄存器组（rs/rd 为源/目的寄存器编号，各 4 位 → 16 个寄存器）、ALU、暂存器 Y 与 Z、标志寄存器 FR、主存，以及连接 CPU 与主存的系统总线。

**控制信号命名规律**：`部件名 + in/out`。

- **out**：该部件向**内部总线**输出，需打开其输出三态门；
- **in**：该部件**从内部总线**接收；
- 还有一类控制信号不控制流向而控制**操作类型**：ALUop（N 位 → 2^N 种操作，题设 000 为加法）、MUX 的选择信号、存储器的读/写信号、PC+1。

**为什么必须有暂存器 Y**：ALU 没有存储能力。若 ALU 两端直接挂总线，先送第一个操作数，下个时钟送第二个操作数时会把前一个覆盖掉，ALU 永远只能看到同一个数。有了 Y，先把第一个数存进去，再送第二个数到另一端，两个不同的数才能运算。**Y 只有 in，没有 out**——它的输出直接连 ALU 输入端，不往总线送，所以不叫 out。

**为什么必须有暂存器 Z**：ALU 的输出若直接连总线，结果会顺着总线回流到自己的输入端，干扰运算。所以先存 Z，再由 Z 经三态门送总线。Z 一般只有 out，没有 in（图上有几个信号就写几个，不要凭空造）。

#### 4. 微操作序列（核心，必须会写）

**取指阶段（任何指令通用，真题考过多次）**

| 序号 | 功能 | 控制信号 | 时钟数 |
|---|---|---|---|
| 1 | (PC) → MAR | PCout, MARin | 1 |
| 2 | M(MAR) → MDR | MEMR（读）, MDRinE | 5（题目给定） |
| 3 | (MDR) → IR | MDRout, IRin | 1 |

合计 **7 个时钟**。其中"1 个时钟""5 个时钟"由题目给出，但第 1、3 步各占 1 个时钟必须自己判断——因为**一个时钟只能有一个 out 信号**。

**加法指令 add R1, R2**（R1 为源、R2 为目的，执行阶段）

| 序号 | 功能 | 控制信号 |
|---|---|---|
| 1 | (R1) → Y | R1out（送 rs 编号选中寄存器）, Yin |
| 2 | (R1) + (R2) → Z | R2out（送 rd 编号）, ALUop=000 |
| 3 | (Z) → R2 | Zout, R2in（送 rd 编号） |

**取数指令 load（寄存器间接寻址）执行阶段**

| 序号 | 功能 | 控制信号 |
|---|---|---|
| 1 | (R1) → MAR | R1out, MARin |
| 2 | M(MAR) → MDR | MEMR, MDRinE |
| 3 | (MDR) → R2 | MDRout, R2in |

对比可见：**取指时 MDR 里是指令、送 IR；取数时 MDR 里是数据、送通用寄存器**。凡是访问内存，必须先把地址送 MAR；凡是从内存进出的数据，必须经过 MDR。

### 四、5.6 流水线

#### 1. 基本概念

- **时间并行** = 流水线技术：多个任务在不同阶段同时推进；
- **空间并行** = 资源重复（超标量）：同一部件配多份，同时干多件事。

五段流水线 IF / ID / EX / MEM / WB，每条指令错开一个阶段启动。不采用流水线则串行执行，某条指令进入后段时前段硬件全部闲置——这正是流水线的动机。

**流水线要求**（了解即可，不要求背）：指令长度尽量统一、格式规整、仅 load/store 访存、按边界对齐（与 RISC 的特征一脉相承）。

**时钟周期**取各流水段中最长（最耗时）的那一段。时间单位换算：1 s = 10³ ms = 10⁶ μs = 10⁹ ns = 10¹² ps。

#### 2. 性能公式（必背，且要会两种理解）

k 段流水线、Δt 为一个时钟周期、执行 n 条指令：

$$T = (k + n - 1)\Delta t$$

两种理解都对：

- **从头算**：第 1 条要 k 个时钟，之后每条只差一个阶段，再补 (n−1) 个 → k + (n−1)；
- **从尾算**：每个时钟启动一条，n 条要 n 个时钟，最后一条还要再走 k−1 段 → n + (k−1)。

由此：

- 实际平均 CPI = (k + n − 1) / n，当 n → ∞ 时 → 1，所以"流水线 CPI ≈ 1"是**近似值**，"n 条指令 n 个时钟"也是近似；精确值是 k+n−1。
- **吞吐率** TP = n / T = n / [(k+n−1)Δt]，单位是"条/秒"，最大值 1/Δt。它与第一章的"指令执行速度 = 主频 / CPI"是一回事，只是后者是未流水线的算法。
- **加速比** S = 顺序执行时间 / 流水线时间 = n·k·Δt / [(k+n−1)Δt] = nk / (k+n−1)，**上限为 k**（n→∞ 时趋近 k）。
- **效率** E = 有效面积 / 总时空图面积 = nk / [k(k+n−1)] = n / (k+n−1)，即时空图被填满的比例。

#### 3. 流水段寄存器

每段之间设**流水段寄存器**，锁存本段的输出结果供下一时钟使用。为什么必须有：

- 若没有，第 2 条指令取指后写入 IR，会把第 1 条指令覆盖掉，而第 1 条还在译码、还要用 IR 的内容；
- 同理 EX 算出的结果若只放在组合逻辑输出端，下一条指令进入 EX 就把它覆盖了，而前一条的 MEM/WB 还要用这个结果。

所以流水段寄存器是"**为后续阶段保住前一条指令的数据**"。它本身也有一点延迟，题目未说明时可忽略。

#### 4. 三类冒险（本章最爱考，数据冒险考得最多）

判断冒险全靠**表格 5.3**（四类指令的五阶段动作，务必先记熟）：

| 指令类型 | IF | ID | EX | MEM | WB |
|---|---|---|---|---|---|
| 运算类 | 取指 | 译码读寄存器 | ALU 运算 | **空** | 写寄存器 |
| load | 取指 | 译码读寄存器 | 算有效地址 | 读内存 | 写寄存器 |
| store | 取指 | 译码读寄存器 | 算有效地址 | 写内存 | **空** |
| 条件转移 | 取指 | 译码读寄存器 | 算目标地址并判断 | **更新 PC** | **空** |
| 无条件转移 | 取指 | 译码读寄存器 | **更新 PC** | **空** | **空** |

**冒险（相关）**：某些情况导致后续指令无法正确执行，从而引起流水线阻塞。

**（1）结构冒险 / 资源冲突**：不同指令在同一时刻争用同一部件。

典型：load 指令在 MEM 段访存，而 I+3 的 IF 段也要访存，两者撞车，只能把 I+3 整体后推一个时钟。注意：运算类指令的 MEM 段是空的，它与后面的 IF 不冲突——**冲突一定发生在"访存类指令的 MEM 段"与"后续指令的 IF 段"之间**。

解决：① 停顿（推迟，插入气泡）；② **增加硬件资源**——指令存储器与数据存储器分离（即指令 Cache / 数据 Cache 分离），两套硬件各干各的，IF 与 MEM 就能同时进行。

串行执行永远不会有结构冒险，但效率极低——冒险正是"用流水线换速度"的代价。

**（2）数据冒险 / 数据相关**：后一条指令要用前一条指令的结果，而前一条还没产生或还没写回。最常见的是 **RAW（写后读）**。

例：`I1: add R1,R2,R3`（写 R1），`I2: sub R4,R1,R5`（读 R1）。I2 在 ID 段就要读 R1，而 I1 要到 WB 段才写回，读早于写。

三种解决办法：

1. **延迟相关指令**（本质都是把 ID 推到 WB 之后）：
   - **硬件阻塞 / 插入气泡（stall）**：硬件自动暂停，把后一条的 ID 推后；
   - **软件插入空操作指令（NOP）**：插入 3 条 NOP，等效把后一条推迟 3 个时钟。NOP 也是指令，也要取指、也要 PC 自增，只是 EX/MEM/WB 什么都不做，不影响结果；
   - **调整指令顺序**：把无关指令提前填进空档，与插 NOP 等效（选择题里"调整指令顺序"也是正确解法）。
2. **转发 / 数据旁路（forwarding / bypass）**：运算类指令在 EX 段末就算出结果，不必等 WB，直接把结果送到下一条指令的 EX 输入端。转发后只需保证"**下一条的 EX 在上一条的 EX 之后**"，而流水线天然错开一个时钟，所以一般无需阻塞。
3. **load-use 冒险**：前一条是 load，后一条紧接着用它的结果。load 的数据要到 **MEM 段末**才取到，EX 段只算出地址，转发也无数据可转。必须"**延迟 + 转发**"：把后一条的 EX 阻塞到前一条 MEM 之后，再从 MEM 输出直接转发给 EX。这类是转发解决不了的特例。

**（3）控制冒险 / 控制冲突**：转移指令、中断/异常改变了 PC，而流水线已经预取了后面的指令。

条件转移在 **MEM 段**才更新 PC（此时才知道是否转移），所以**下一条指令的 IF 必须放在转移指令的 MEM 之后**。无条件转移在 EX 段就更新 PC，只需等到 EX 之后。

解决：插入空操作 / 硬件阻塞（气泡）、**分支预测**（预测不转移则继续取指；预测转移则用转移目标地址取指）、延迟转移等。基础阶段重点掌握"阻塞到 MEM 之后"这一种。

#### 5. 高级流水线

| 技术 | 做法 | CPI |
|---|---|---|
| 多发射（动态）= **超标量** | 配置多套功能部件，每时钟同时启动多条指令，需**动态调度**技术处理相关性 | **< 1** |
| 多发射（静态）= **超长指令字 VLIW** | 编译器把多条可并行的指令打包成一条超长指令 | < 1 |
| **超流水线** | 增加流水段数（如 5 段 → 8 段），阶段更细、时钟更短、主频更高 | = 1 |

超流水线的 CPI 仍是 1（每时钟仍完成一条），但时钟周期变小、主频变高，所以每秒执行的指令更多。**多发射才是 CPI < 1**。

## 老师强调的考点

1. **第五章的大题只出在 5.3 数据通路和 5.6 流水线**，其余小节只出选择题——时间分配按此倾斜。
2. **取指微操作序列必须背下来**：`(PC)→MAR，M(MAR)→MDR，(MDR)→IR`，历年真题考过很多次，"提到取指就要会默写"。
3. **写控制信号是真题原题问法**：给你单总线图，让你写出某条指令每个节拍的功能与控制信号，考过不止一次。
4. **必考：单总线的"一个时钟只能有一个 out 信号"**——据此判断两条微操作能否合并到同一时钟。
5. **公式必背**：`T=(k+n−1)Δt`、`CPI=(k+n−1)/n`、`S=nk/(k+n−1)<k`，计算题年年要用。
6. **常考（选择题）**：哪些寄存器对用户可见/不可见；IR、MAR、MDR 一定不可见，PSW 可见但只读，移位寄存器按不可见记。
7. **常考**：PC 位数计算，尤其"指令按边界对齐"这一条件，真题考过一次、极易误选。
8. **常考**：机器字长 = ALU 位数 = 通用寄存器位数。
9. **选择题爱考**：数据冒险中"写后读不一定冲突"——中间隔够 3 条指令就无冲突；以及"调整指令顺序"也是数据冒险的解法。
10. **大题爱考**：画多条指令的五段时空图，判断哪两条有数据冒险、哪几条被阻塞、共需多少时钟。
11. **大题爱考**：单总线数据通路下 ADD (R1),R0 这类题的微操作序列，含"至少需要多少时钟"的优化问。
12. **常考**：结构冒险的解决办法是指令/数据存储器（Cache）分离；load-use 必须"延迟 + 转发"，单纯转发不行。
13. **概念题反复考**：单周期/多周期/基本流水线/超标量的 CPI 与 1 的大小关系。
14. **小问考过**：实现单总线数据通路需要什么硬件——答案是**三态门**（以及暂存器）。

## 快速技巧与口诀

**数据通路大题答题模板（四步）**

1. **读图**：圈出所有能 out 到总线的部件（每个都带三态门）、能 in 的部件、ALU 两个输入端的来源、暂存器有无 in/out 信号、系统总线与 CPU 内部总线各接什么。
2. **拆指令**：先判断寻址方式——看到 `(R1)` 就是寄存器间接（R1 里是地址），`R1` 是寄存器寻址（R1 里是数据），`((R1))` 是两级间接；再决定要不要访存。
3. **写微操作**：一条微操作 = "（源）→ 目的"，按数据流顺序排列。固定套路：
   - 要访存 → 先把地址送 MAR；
   - 内存 ↔ CPU → 必经 MDR；
   - 两个操作数运算 → 必有一个先进暂存器 Y；
   - 结果回总线 → 必经 Z。
4. **配控制信号**：源部件加 `out`，目的部件加 `in`；访存加 `MEMR/MEMW`；运算加 `ALUop`；进出内存的 MDR 用 `MDRinE/MDRoutE`（走系统总线），走 CPU 内部总线的用 `MDRin/MDRout`；寄存器组还要给出 rs/rd 编号。**最后检查：每个时钟是否只有一个 out。**

**能否合并到同一时钟的判据**：两条微操作**无逻辑先后**且**不共用同一组总线/部件** → 可合并（如 `R0→A` 走 CPU 总线、`M(MAR)→MDR` 走系统总线）；有逻辑先后（地址没进 MAR 不能访存、AC 没进 MDR 不能写内存）或同一时钟出现两个 out → 必须分开。

**流水线三类公式速记**

- 时间：**T = (k + n − 1)Δt**（"k 是启动开销，n 是流水线本体"）；
- 吞吐率：**TP = n / T**，极限 1/Δt；
- 加速比：**S = nk / (k + n − 1)**，极限 k，**永远达不到 k**；
- 效率：**E = n / (k + n − 1)**。

**三类冒险一句话口诀**

- **结构冒险**——"抢同一个部件"：load 的 MEM 撞 I+3 的 IF → 拆硬件（指令/数据存储器分离）或停一拍。
- **数据冒险**——"写没写完就要读"（RAW）：能转发就转发（EX 接 EX），转不了就延迟（ID 挪到 WB 后）；load-use 特殊，只能"等一拍再转发"（EX 挪到 MEM 后）。
- **控制冒险**——"PC 还没定就取指"：条件转移 MEM 才定 PC → IF 挪到 MEM 后；或分支预测。

**时空图画法**：每条指令一行、每时钟一列，五段依次填格；遇冒险画叉阻塞、后续段整体右移，**"需多少时钟"= 最后一格列号**。

## 易错点与坑

1. **PC 自增的时机与增量**。取指阶段一取出指令就更新 PC（不是执行完才更新），这样下条指令的地址随时可用；增量是"指令占的地址单元数"，不是"字节数"，按字编址时要除以字长。
2. **PC 位数 ≠ MAR 位数**。指令按边界对齐时，PC 只需能区分"第几个指令槽"，位数比 MAR 少 log2(指令字节数) 位，送 MAR 时要左移（×4）。这是真题设过的坑，绝大多数无对齐的题里二者才相等。
3. **MAR 与 MDR 的位数不是一回事**。MAR 位数由**地址总线宽度/存储单元数**决定，MDR 位数由**存储字长/数据总线宽度**决定，二者相互独立，别都当成"机器字长"。
4. **MDRin 与 MDRinE 不能混**。`MDRinE` 表示从**数据总线（内存侧）**写入 MDR，`MDRoutE` 表示送往数据总线；`MDRin/MDRout` 走 **CPU 内部总线**。教材例题取指第三步写了 `MDRin` 是**错的**（应删去），老师专门指出。
5. **单总线为什么必须加暂存器**：ALU 无记忆功能，两端直连总线会互相覆盖；ALU 输出直连总线会反馈干扰自身输入。这两个理由要能各说一句。
6. **Y 没有 out、Z 没有 in**。信号以图为准，"图上有几个就写几个"，不要凭想象补信号。
7. **流水段寄存器不是"多余的一级"**。它锁存前一条指令的结果，防止被后一条覆盖（IR 被覆盖、EX 结果被覆盖），不是单纯增加延迟。
8. **"写后读"不等于"一定冲突"**。中间隔了 ≥3 条指令（对五段流水线）时，读已自然落在写之后，不再有冒险。
9. **加速比达不到 k**。S = nk/(k+n−1) < k，只在 n→∞ 时趋近 k；不要写成"等于 k"。
10. **超标量 ≠ 超流水线**。超标量是**空间**并行（多套硬件、CPI<1）；超流水线是**时间**上把段分得更细（CPI 仍 = 1，靠提高主频提速）。动态多发射 = 超标量，静态多发射 = VLIW，这两个不要对调。
11. **控制冒险的阻塞位置**：条件转移阻塞到 **MEM 之后**（不是 EX 之后）；无条件转移在 EX 段就改 PC，只需等到 EX 之后。

## 本章例题

### 例1（5.1 课后 23，真题）PC 的位数

**题干要点**：主存 4 GB，按字节编址，字长 32 位，指令字长 32 位且**按边界对齐**。问 PC 与 IR 的位数至少各是多少。

**解题步骤**

1. 4 GB 按字节编址 → 共 2³² 个地址单元，地址线 32 位，MAR 为 32 位。
2. IR 存放整条指令 → 至少 32 位。
3. 指令 4 字节且按边界对齐 → 首地址必须是 4 的整数倍，只能放在 0、4、8、12…… 这些位置，即**每 4 个地址才有一个可放指令**。
4. 可放指令的位置数 = 2³² / 4 = 2³⁰ → PC 只需 30 位。
5. PC 送 MAR 时左移 2 位（×4）才能还原成真实地址。

**答案**：IR = 32 位，PC = 30 位（选 B）。若**不考虑**边界对齐（每个地址都能起放指令），则 PC = 32 位，与 MAR 相同。这类"PC 与 MAR 不等"的考法只考过一次，多数真题属于无对齐的情形。

### 例2（5.3 教材例）单总线下的 add 与 load

**题干要点**：单总线数据通路，寄存器编号 4 位（共 16 个寄存器），ALUop=000 为加法。写出 `add R1,R2`（(R1)+(R2)→R2）与 `load (R1),R2`（((R1))→R2）执行阶段的微操作与控制信号。

**解题步骤**

`add R1,R2`：

| 时钟 | 功能 | 控制信号 |
|---|---|---|
| 1 | (R1) → Y | R1out, Yin |
| 2 | (R1)+(R2) → Z | R2out, ALUop=000 |
| 3 | (Z) → R2 | Zout, R2in |

`load (R1),R2`：

| 时钟 | 功能 | 控制信号 |
|---|---|---|
| 1 | (R1) → MAR | R1out, MARin |
| 2 | M(MAR) → MDR | MEMR, MDRinE |
| 3 | (MDR) → R2 | MDRout, R2in |

**答案**：如上。要点是"访存先送 MAR、内存数据必过 MDR、双操作数必有一个进 Y、结果必过 Z"。取指阶段两者完全相同，都是 3 步 7 个时钟。

### 例3（5.3 课后 7，09 年真题）ADD (R1), R0 的微操作

**题干要点**：机器字长 16 位，指令字长 16 位，控制信号为 1 有效。指令 `ADD (R1), R0`，功能为 ((R1)) + (R0) → (R1)，即 R0 用寄存器寻址、R1 用寄存器间接寻址、结果写回 R1 所指内存单元。已给取指阶段的节拍，要求仿写执行阶段每个节拍的功能与控制信号。信号中 `MDRinE/MDRoutE` 走数据总线（DB），`MDRin/MDRout` 走 CPU 内部总线，MAR 输出始终使能。

**解题步骤**（一种写法）

| 节拍 | 功能 | 控制信号 |
|---|---|---|
| C5 | (R1) → MAR | R1out, MARin |
| C6 | M(MAR) → MDR | MEMR, MDRinE |
| C7 | (R0) → A（暂存器） | R0out, Ain |
| C8 | (A) + (MDR) → AC | MDRout, ALUop, ACin |
| C9 | (AC) → MDR | ACout, MDRin |
| C10 | (MDR) → M(MAR) | MDRoutE, MEMW |

**优化问**：若问"至少多少时钟"，C6 与 C7 可合并——一个走系统总线、一个走 CPU 内部总线，硬件独立、无逻辑先后，故 6 个时钟可压到 **5 个**。其余各步都有逻辑先后（地址不进 MAR 不能访存；AC 不进 MDR 不能写内存），不能合并。

**其他合法写法**：把 MDR 的内容先送暂存器、R0 直接上 ALU 另一端，也完全正确——**两个操作数谁先进暂存器没有标准答案**，只是多花一个时钟。书上只给了一种，实际有三种等价写法。

**答案**：如上表；最少 5 个时钟。此题的价值在于吃透 `inE/outE` 与 `in/out` 的区别，以及"MAR 一直使能所以地址可复用"这一设定。

### 例4（5.6 课后 24）数据冒险的判断与时空图

**题干要点**：给出四条指令（I2 写 R5、I3 读 R5 等），问哪两条之间存在数据冒险；并画出时空图、求总时钟数。

**解题步骤**

1. 只看**写后读**：前一条写某寄存器，后一条读同一寄存器。
2. I1 写 R1，I2 读 R2、R4 → 无关；I2 写 R5，I3 读 R5 → **有冒险**；I2 写 R5，I4 读 R2、R6 → 无关；I3 写 R4，I4 读 R2、R6 → 无关。
3. 画时空图：四条指令各五段，遇 I3 的 ID 需等 I2 的 WB，画叉右移；其余正常错开一格。
4. 数格子：共 **11 个时钟**。

**答案**：仅 I2 与 I3 存在数据冒险（选 B）；按字幕的画法，四条指令排下来共 **11 个时钟**。**课后 28 题同理**：逐对查写-读，I1 写 R2 与 I3 读 R2、I2 写 R3 与 I3 读 R3、I3 写 R2 与 I4 读 R2 均冲突，只有 I2 写 R3 与 I4 读 R2 无关，选 C。注意：两条相关指令之间隔了三条以上指令时，读已自然落在写之后，不构成冒险——"写后读"只是必要条件。

### 例5（5.6 课后 30）转发 + 控制冒险综合

**题干要点**：五段流水线，数据冒险用**转发**处理，控制冒险用**硬件阻塞（气泡）**处理。给出 I1–I4（I2 为 load，I3 用其结果，I4 前一条为 BEQ 分支），问哪几条指令发生阻塞。

**解题步骤**

1. I1 正常五段。
2. I2 与 I3：I2 是 load，I3 要用其写回值 → **load-use 冒险**，转发不够，须"延迟 + 转发"：把 I3 的 EX 阻塞到 I2 的 MEM 之后。
3. I3 与 I4：I4 的前一条是 BEQ 条件转移，PC 要到 MEM 才确定 → I4 的 IF 必须阻塞到 I3 的 MEM 之后。
4. 结论：I3、I4 都发生阻塞，其余正常。

**答案**：**I3 与 I4 发生阻塞**。注意真题画法与教材图不同：教材常从 IF 开始整条后移，真题只需**阻塞出问题的那一段**（该阻塞 IF 就阻塞 IF，该阻塞 EX 就阻塞 EX）。

### 例6（5.6 课后 29、20、23）CPI 与概念辨析

**29 题**：单周期 = 1；多周期 > 1；基本流水线 = 1（每时钟完成一条）；超标量 < 1（并行多条，平均每条不到一个时钟）。这四个"1 / >1 / =1 / <1"必须条件反射。

**20 题**：不会引起流水线阻塞的是 **数据旁路（转发）**——它是数据冒险的**解决方案**；资源冲突、数据相关、条件转移才是阻塞的**原因**。

**23 题**：指令 Cache 与数据 Cache 分离解决的是**资源冲突（结构冒险）**：取指访指令 Cache、访存访数据 Cache，两套硬件使 IF 与 MEM 可同时进行。
