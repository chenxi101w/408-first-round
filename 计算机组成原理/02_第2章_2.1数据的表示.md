## 知识点详解

### 一、进位计数制与标识

R 进制每一位只能取 0 ~ R-1。十进制 0~9 共十个数；二进制 0~1；八进制 0~7；十六进制 0~15，其中 10~15 用 A~F 表示（A=10，D=13，F=15），大小写均可。

**同一个数字串在不同进制下数值不同**，所以真题常用后缀/前缀标注：

| 后缀/前缀 | 含义 | 备注 |
|---|---|---|
| `B` | 二进制 | 注意此处 B 是 Binary，不是 Byte |
| `O` | 八进制 | |
| `D` | 十进制 | 通常省略，默认即十进制 |
| `H` | 十六进制 | 如 `2328H` |
| `0X` | 十六进制前缀 | 如 `0X2328` |

### 二、按权展开（任意进制 → 十进制）

规则：每一位的数值 × 该位的权重，权重 = 基数^（该位右边还有几位）。

- 十进制：1234 = 1×10³ + 2×10² + 3×10¹ + 4×10⁰
- 二进制：1011B = 1×2³ + 0×2² + 1×2¹ + 1×2⁰ = 11
- 十六进制：B6FD H = 11×16³ + 6×16² + 15×16¹ + 13×16⁰
- 八进制：6724O = 6×8³ + 7×8² + 2×8¹ + 4×8⁰
- 小数：123.456 = 1×10² + 2×10¹ + 3×10⁰ + 4×10⁻¹ + 5×10⁻² + 6×10⁻³

小数点后第一位权重是基数的 −1 次方，往后依次 −2、−3。

### 三、十进制 → 二进制：除基取余（整数）

**原理**：第一次除 2 得到的余数就是**最低位**，因为只有最低位不能被 2 整除。所以余数要**从下往上**（即从后往前）写。

例：86 → 二进制

```
86 ÷ 2 = 43 余 0   ← 最低位
43 ÷ 2 = 21 余 1
21 ÷ 2 = 10 余 1
10 ÷ 2 =  5 余 0
 5 ÷ 2 =  2 余 1
 2 ÷ 2 =  1 余 0
 1 ÷ 2 =  0 余 1   ← 商为 0 停止
```

自下而上读：**1010110**。验算：2⁶+2⁴+2²+2¹ = 64+16+4+2 = 86。

求十六进制就除 16 取余，求八进制就除 8 取余，逻辑完全一样。

例：9000 → 十六进制

```
9000 ÷ 16 = 562 余 8
 562 ÷ 16 =  35 余 2
  35 ÷ 16 =   2 余 3
   2 ÷ 16 =   0 余 2
```

自下而上：**2328H**。

### 四、十进制 → 二进制：拼凑法

把数拆成 2 的幂之和，再按「有没有这一位」从低位往高位写 0/1。

例：278 = 256 + 16 + 4 + 2 = 2⁸ + 2⁴ + 2² + 2¹

从 2⁰ 开始逐位问「有没有」：2⁰ 无→0，2¹ 有→1，2² 有→1，2³ 无→0，2⁴ 有→1，2⁵~2⁷ 无→000，2⁸ 有→1，得 **100010110**。

例：9000 = 8192 + 512 + 256 + 32 + 8 = 2¹³+2⁹+2⁸+2⁵+2³ → **10001100101000**。

拼凑法比连续除 2 快得多（9000 要除十三四次，写一大片竖式），所以老师推荐日常优先用拼凑法。

### 五、二 ↔ 十六 / 二 ↔ 八

因为 16 = 2⁴，**每 4 位二进制对应 1 位十六进制**；因为 8 = 2³，**每 3 位对应 1 位八进制**。

分组补零方向（书上有强调）：

- **整数部分**不足一组：在**高位（左侧）补 0**
- **小数部分**不足一组：在**低位（右侧）补 0**

例（教材例 2.1）：二进制 `1111000010.01101`

- 转八进制，每 3 位：`001 111 000 010 . 011 010` → **1702.32**
  验算：1×8³+7×8²+0×8+2 = 512+448+2 = 962 = 0x3C2 ✔；0.32 八进制 = 3/8+2/64 = 0.40625 ✔
- 转十六进制，每 4 位：`0011 1100 0010 . 0110 1000` → **3C2.68**
  验算：0.68H = 6/16 + 8/256 = 0.40625 ✔

反之，十六进制转二进制时把每位写成 4 位二进制（`2`→`0010`，`3`→`0011`，`8`→`1000`），八进制每位写 3 位。

### 六、小数：乘 2 取整

整数用「除 2 取余」，小数用「**乘 2 取整**」，且取出的整数位是**从高位往低位**（先得到的写在最靠近小数点处）。

例：0.6875

```
0.6875 × 2 = 1.375  → 取 1，余 0.375
0.375  × 2 = 0.75   → 取 0
0.75   × 2 = 1.5    → 取 1，余 0.5
0.5    × 2 = 1.0    → 取 1，余 0.0 → 停止
```

结果：**0.1011B**（十进制 0.6875，别和十进制 0.1011 混淆）。拼凑法同样可用：0.6875 = 0.5 + 0.125 + 0.0625 = 2⁻¹+2⁻³+2⁻⁴。

**并非所有十进制小数都能精确转二进制。** 例：0.3

```
0.3×2 = 0.6 → 0
0.6×2 = 1.2 → 1，余 0.2
0.2×2 = 0.4 → 0
0.4×2 = 0.8 → 0
0.8×2 = 1.6 → 1，余 0.6   ← 回到 0.6，开始循环
```

得到 0.0100110011001…，循环节 1001，永远得不到 0.0。**十进制整数一定能转二进制，十进制小数不一定能。**

完整例（教材例 2.2）：123.6875 → 整数部分 123 = 1111011，小数部分 0.6875 = 0.1011，合起来 **1111011.1011B**。

### 七、机器数与真值

- **机器数**：数字在机器里的二进制形式（含符号位）。
- **真值**：这个机器数真正代表的数值。

同一个机器数 `1101`，在不同约定下真值完全不同：

| 约定 | 真值 |
|---|---|
| 无符号数 | 13 |
| 有符号数（符号位 + 数值，原码理解） | −5 |
| 定点小数（小数点默认在符号位后） | −0.625（= −(0.5+0.125)） |
| 定点整数（小数点默认在最低位后） | −5 |

这两个术语是第二章最重要的两个名词，后面所有编码题本质都是「机器数 ↔ 真值」。

### 八、定点小数与定点整数

- **定点小数**：只能表示**纯小数**，形如 0.xxxx。小数点约定在**符号位之后、数值位之前**。所以 `1101` 是「符号 1（负），小数 0.101」= −0.625，绝不能读成 −1.101。
- **定点整数**：只能表示**纯整数**，小数点约定在**数值部分最低位之后**。

**小数点并不真正存储**，只是人为约定。题目一定会说明是定点小数还是定点整数；若没说明，真题默认按**定点整数**处理。

### 九、原码

符号位：0 正、1 负；其余位是绝对值的二进制。

`+7` → `0111`；`−7` → `1111`；`+5` → `0101`；`−5` → `1101`。

范围（n 位，1 符号 + n−1 数值）：**−(2^(n-1)−1) ~ +(2^(n-1)−1)**，关于 0 对称。零有**两种**表示：`0000`（+0）和 `1000`（−0）。

优点：与真值对应直观，求乘法除法简便。缺点：加减运算复杂（要先判符号、比绝对值大小）。

### 十、补码（考评最高）

- 正数：补码 = 原码。
- 负数：**符号位不变，其余各位按位取反，末位加一**。反码与补码互转规则完全一样。

例：−5 的原码 `1101`

```
原码  1 1 0 1
取反  1 0 1 0   （符号位不动）
加 1  1 0 1 1   → 补码 1011
```

补码 `1011` 求原码也是同一套：`1011` → 取反 `1100` → 加 1 → `1101`。

**注意加 1 的位置**：是「取反后的结果」再加 1，不是原码、取反、1 三行相加。

范围（n 位）：**−2^(n-1) ~ 2^(n-1)−1**，负数比正数**多一个**。8 位即 **−128 ~ +127**，4 位即 −8 ~ +7。零的表示**唯一**（`0000`）。

优点：符号位可与数值位一起参加运算，减法变加法，加减法电路简单。缺点：与真值对应不直观，要转成原码才看得懂数值。

### 十一、反码

- 正数：反码 = 原码。
- 负数：**符号位不变，其余各位取反**（不加 1）。

反码就是「原码 → 补码」的**中间步骤**，考试基本不单独考，知道定义即可。零同样有 +0 / −0 两种。

### 十二、补码与真值互转的快速求法（最高频技巧）

**核心恒等式**：对负数，`[x]补 + |x| = 2ⁿ`，即补码加上它的绝对值，会「**进一位，后面全 0**」。所以反过来：**看补码加上多少能凑成「1 后面全 0」，加的那个数就是绝对值。**

十六进制口算时，凑的目标是 `100…0`（后面全 0），所以：

- `F8` + 8 = `100` → 真值 −8
- `FA` + 6 = `100` → 真值 −6（A=10，10+6=16 进一）
- `FF` + 1 = `100` → 真值 −1
- `90` + `70` = `100` → 真值 −112（0x70 = 7×16 = 112）
- `FFFFFFD3` + `2D` = `100000000` → 真值 −45（3+13=16 进一，前面的 F 依次被进位吃满）
- `FFFF A8BC` + `5744` = `10000` → 真值 −0x5744

口算要领：**从最低位往上凑 16，最低位凑成 16 后进位，前面每一位只要凑 15（F），连同进位就变 16**。所以规律是「末位补到 16，其余位补到 15」。

二进制同理，凑「1 后全 0」：

| 补码 | 加 | 结果 | 真值 |
|---|---|---|---|
| 1011 | 0101 (5) | 10000 | −5 |
| 1101 | 0011 (3) | 10000 | −3 |
| 1110 | 0010 (2) | 10000 | −2 |
| 1111 | 0001 (1) | 10000 | −1 |

**判断正负**：十六进制首位 **≥ 8 就是负数**，≤ 7 就是正数（因为 8~F 转成 4 位二进制都是 1 开头，0~7 都是 0 开头）。正数补码直接按权展开即可，不需要技巧。

**反向用**：求真值 x 的补码，先写 |x| 的十六进制，再找「谁加上它进位成全 0」，那个数就是补码。

- −45 的 32 位补码：|−45| = 2D → `FFFFFFD3`
- −8 的 32 位补码：`FFFFFFF8`
- +45 的 32 位补码：`0000002D`（正数高位全补 0）

这个技巧**不是万能的**，但真题里大量出现；常规「先求原码再求真值」的方法也必须会，两种方法都要练。

### 十三、补码求真值的五种方法（以 8 位补码 `1101 0110` = D6H 为例）

**方法 1：先求原码（最常用）**
符号位不变，最右的 1 及其右边的 0 不变，其余取反：`1101 0110` → `1010 1010` = −(2⁵+2³+2¹) = −(32+8+2) = **−42**

**方法 2：当无符号数，用 2ⁿ 减**
把 8 位整体当无符号数：2⁷+2⁶+2⁴+2²+2¹ = 128+64+16+4+2 = 214；2⁸ − 214 = 256 − 214 = 42 → **−42**

**方法 3：转十六进制凑 100**
D6 + 2A = 100 → 绝对值为 2A = 2×16+10 = 42 → **−42**

**方法 4：偏移量法（一全零 + 偏移）**
`1000 0000` 的真值是 −2⁷ = −128，低位偏移量为 `0101 0110` = 64+16+4+2 = 86，故 −128 + 86 = **−42**

**方法 5：直接按位权（首位负权）**
最高位权重取 −2⁷，其余位取正权：
−2⁷ + 2⁶ + 2⁴ + 2² + 2¹ = −128+64+16+4+2 = **−42**

**两个必须背下来的特殊补码**：
- **全 1** 的补码，真值一定是 **−1**（任何位数）。
- **1 后面全 0** 的补码，真值是 **−2^(n-1)**（8 位即 −128，后面几个 0 就是 2 的几次方）。这个**无法**用「取反加一」推出来（推出来会得到 0 开头，符号都变了），只能记。

### 十四、移码

**定义**：`[x]移 = 真值 x + 偏置值`，偏置值通常取 **2^(n-1)**（n 为机器数总位数）。

思想：把真值整体「放大/平移」，让所有数都变成非负数，同时**保持原来的大小顺序**。

4 位示例（偏置 4）：

| 真值 | −4 | −3 | −2 | −1 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|---|---|---|---|
| 加 4 后 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| 移码 | 000 | 001 | 010 | 011 | 100 | 101 | 110 | 111 |
| 补码 | 100 | 101 | 110 | 111 | 000 | 001 | 010 | 011 |

**结论（偏置取 2^(n-1) 时）**：移码与补码**仅最高位（符号位）相反**，把补码最高位取反即得移码。

**移码求真值两条路**：
1. 把移码当无符号数求值，再减偏置。8 位全 1 移码：255 − 128 = **+127**。
2. 最高位取反得补码，再按补码求真值。

**求真值的移码**：x + 偏置，再转二进制。127 + 128 = 255 = `1111 1111`。

**重要提醒**：书上写的是「n+1 位、数值位 n 位、偏置 2ⁿ」，和这里「总位数 n、偏置 2^(n-1)」是同一件事，别被符号绕晕。**一旦题目换了偏置值，「移码 = 补码最高位取反」「移码全 0 是最小值」这些结论全部失效**，只能按定义算。IEEE 754 的阶码偏置是 **2^(k-1) − 1**（8 位阶码为 127），又差一个 1，2.3 节再讲。

移码的特点：保持了真值的大小顺序（移码越大真值越大，与偏置取值无关），所以浮点数阶码用它；移码**只用于整数**，小数没有移码。

### 十五、补码的数轴（圆环）与比较大小

4 位补码按二进制递增排列：

```
000  001  010  011 | 100  101  110  111
 0    1    2    3  | -4   -3   -2   -1
```

从 0 到 3 连续上升，然后「跳」到 −4，再连续升到 −1，最后回到 0 —— 是一个**圆环**。

两条推论：

1. **同号比较**：两个都是正数（或都是负数）时，**直接把补码当无符号数比大小**即可，补码大真值就大。`111` > `100` 即 −1 > −4；`011` > `000` 即 3 > 0。
2. **异号比较**：先看符号，正数 > 负数。十六进制首位 ≤7 为正，≥8 为负。

**偏移量性质**：真值加 k，补码也加 k（模 2ⁿ 意义下）。例：−3 的补码 `101`，加 2 得 `111`，正好是 −1 的补码；`FFF8`（−8）加 5 得 `FFFD`（−3）。所以同一道题里只要求出一个选项的值，其余选项可以靠「补码差多少」直接口算。例：9D = −99，则 9E = −98，96 = −99−7 = −106。

### 十六、无符号数与有符号数

- **无符号数**：全部二进制位都是数值位。8 位范围 **0 ~ 255**（0 ~ 2⁸−1），16 位 **0 ~ 65535**。
- **有符号数**：最高位是符号位，0 正 1 负，计算机内部**默认用补码**。8 位补码范围 **−128 ~ +127**。

用途：**内存地址、指针一律是无符号数**。后续章节提到「主存地址」不再说明时，自己要知道它是无符号数。

## 老师强调的考点

1. **进制转换是必考基本功**（不直接考，但几乎所有计算题都要用），必须练到「看到就会」而不是「想想才会」。
2. **补码是四种编码里考评最高的**，原码、反码、移码都要会，但补码是绝对重点。
3. **补码 ↔ 真值的快速求法「极其高频」**，选择题、大题小问都会用，必须会口算。
4. **原码与补码的表示范围必考**：原码 ±(2^(n-1)−1)，补码 −2^(n-1)~2^(n-1)−1，补码多表示一个负数。
5. **−128（8 位）的特殊性常考**：只有补码能表示，没有原码和反码。
6. **移码与补码仅符号位相反**（偏置 2^(n-1)）这个结论常考；偏置变了就不能用。
7. **补码比较大小（选择题爱考）**：给几个十六进制补码排序，直接用「无符号比较」秒杀。
8. **补码数轴/圆环、偏移量**是选择题爱考的隐藏技巧，也是大题小问的基础。
9. **零扩展 / 符号扩展**：选择题常考，强化阶段的大题小问也会用到，基础阶段必须打扎实。
10. **32 位补码与十六进制互写**（如 `FFFFFFD3`）常出现在选择和大题中。
11. **类型转换的综合题（如 34 题）是易错真题**，当年正确率不高，规则必须记死。
12. **2 的幂要熟**：2¹⁰=1024、2¹²=4096、2¹⁵=32768、2¹⁶=65536，真题中 32767、65535 这类数出现频率极高。

## 快速技巧与口诀

1. **除基取余，从下往上；乘基取整，从上往下。**
2. **按权展开**：一位右边还有几位，就是几次方。
3. **十六进制判正负**：首位 ≥ 8 为负，≤ 7 为正。
4. **原码 ↔ 补码快速法**：符号位不变，**最右的 1 和它右边的 0 不变，其余取反**（正反两个方向规则相同）。比「取反加一」快得多，今后一律用这个。
5. **补码求真值（口算王）**：补码加上多少能凑成「1 后全 0」，这个数就是绝对值——末位凑 16，其余位凑 15（F）。
6. **全 1 补码 = −1**；**1 后全 0 补码 = −2^(n-1)**（8 位 −128）。
7. **2ⁿ − x**：把补码当无符号数算出来，用 2ⁿ 减它即得绝对值（8 位用 256 减）。
8. **首位负权法**：补码求真值 = −(最高位权) + 其余位按正权求和，一步到位。
9. **偏移量法**：−128 + 低位偏移量；反过来真值加 k 补码也加 k，可用于同题多选项连锁口算。
10. **数轴记忆**：4 位补码 `000~011` 是 0~3，`100~111` 是 −4~−1，转一圈回到 0。同号直接比、异号看符号。
11. **移码 = 补码最高位取反**（偏置 2^(n-1)）。
12. **n 个 1 = 2ⁿ − 1**；**1 后面 n 个 0 = 2ⁿ**。
13. **凑 2 的幂时优先用全 1 做减法**：250 = 255 − 5（**不要**写成 256 − 6，会连续借位，反而更慢）。
14. **65530 = 65535 − 5 = 16 个 1 减 5**，比短除法快得多。
15. **零扩展补 0、符号扩展补符号**：正数补 0、负数补 1，扩展后数值不变。
16. **先扩位、后改符号性**：16 位有符号 → 32 位无符号，要先符号扩展到 32 位，再按无符号解释。

## 易错点与坑

1. **补码范围不对称**：n 位补码是 −2^(n-1) ~ 2^(n-1)−1，负数比正数多一个，别写成对称的 ±(2^(n-1)−1)。
2. **−128 没有原码和反码**（8 位）。它的补码是 `1000 0000`，若硬套「取反加一」求原码，会算出 0 开头的正数，逻辑上不成立。
3. **`1000 0000` 不能读成 0**：作为补码它是 −128，作为原码才是 −0。看到 `1` 后全 0 必须分编码讨论。
4. **移码偏置别记混**：常规偏置是 2^(n-1)（n 为总位数），IEEE 754 阶码偏置是 2^(k-1)−1。偏置一换，「移码 = 补码符号位取反」「移码全 0 = 最小值」立即失效。
5. **定点小数误读**：`1101` 作为定点小数是 −0.625，不是 −1.101，也不是 −5。符号位后就是小数点。
6. **小数点不存储**，题目不说是定点小数就按定点整数算。
7. **有符号/无符号混用**：机器数一个位都不变，只是换一种解释方式。`1011` 当无符号是 11，当补码是 −5。
8. **类型转换方向**：长转短只保留低位，**可能改变数值**；短转长必须扩展，**数值一定不变**。
9. **扩展方式选错**：无符号用零扩展，有符号（补码）用符号扩展。给负数补 0 会得到完全不同的值。
10. **同时跨字长和跨符号性时顺序错**（34 题的坑）：必须**先按自身类型扩展到相同字长**，再做有符号/无符号的解释转换；反过来先转无符号再零扩展，会得到另一个（而且卷面上真有这个干扰项）。
11. **分组补零方向**：整数高位补、小数低位补，反了结果全错。
12. **小数转二进制可能死循环**：算到出现重复余数就说明无法精确表示（0.3 的循环节是 1001），不要硬算。
13. **取反加一时对符号位也取反**：负数求补码符号位必须保持 1 不动。
14. **「取反加一」加错位置**：是取反结果加 1，不是原码、取反、1 三行相加。
15. **十六进制与十进制混淆**：`68H` ≠ 68；写答案时务必带上进制标识或换算成十进制。

## 本章例题

**例 1（教材例 2.1）** 二进制 `1111000010.01101` 转八进制、十六进制。
解：整数部分每 3 位一组 `001 111 000 010` → 1、7、0、2；小数部分 `011 010` → 3、2，得 **1702.32（八进制）**。
每 4 位一组 `0011 1100 0010` → 3、C、2；小数 `0110 1000` → 6、8，得 **3C2.68（十六进制）**。

**例 2（教材例 2.2）** 123.6875 转二进制。
解：123 除 2 取余得 1111011；0.6875 乘 2 取整（1、0、1、1）得 0.1011。结果 **1111011.1011B**。

**例 3（课后 16 题）** 8 位机器数 `1000 0000`，分别按四种编码求真值。
解：原码 = −0（即 0）；补码 = −2⁷ = −128；反码 = −(2⁷−1) = −127；移码 = 128 − 128 = 0。
要点：问「真值为 0」时原码（负零）与移码都对应 0，老师按原码作答；问「−128」时只有补码。**结论：−128 是补码独有的。**

**例 4（课后 17、18 题）** 机器数全 1（`1111 1111`）。
解：原码 −(2⁷−1) = −127；补码 **−1**；反码 −0 = 0；移码 255 − 128 = +127。
若问「真值为 127」→ 移码；问「真值为 −1」→ 补码。全 1 补码为 −1 是必背结论。

**例 5（课后 19 题）** 机器数 `0000 0000`，求真值 −128 时的编码。
解：原码 +0、补码 0、反码 0、移码 = 0 − 128 = **−128**。答案：移码。

**例 6（课后 20 题）** 定点小数真值 −0.1101，求原码、反码、补码。
解：原码 `1.1101`；反码（符号位不动，其余取反）`1.0010`；补码 `1.0011`。答案 C（补码）。
要点：**小数同样适用「符号位不变、最右 1 及其右边 0 不变、其余取反」**，小数点只是心里知道，不参与运算、不存储。小数**没有移码**。

**例 7（课后 22 题）** 用 8 位、两个 0 和六个 1 构造补码/移码，求最小、最大整数。
解：
- 补码最小：让 1 尽量靠后 → `1001 1111`，偏移量 31，−128+31 = **−97**（C）
- 补码最大：符号 0，1 尽量靠前 → `0111 1110` = **126**（D）
- 移码最小：同样让 1 靠后 → `0011 1111` = 63，63 − 127 = **−64**（A）
- 移码最大：1 靠前 → `1111 1100` = 252，252 − 128 = **124**（B）（原文此出口播含糊，按移码定义算得 124）
答案 **A**。要点：移码同样「码越大真值越大」，且偏置不同结果不同。

**例 8（课后 28 题）** 8 位补码，用两个 1、六个 0 表示，求最小整数（并追加最小负数、最大负数、最大整数）。
解：
- 最小整数 = 最小负数：`1000 0011` = −128+3 = **−125**
- 最大负数：`1110 0000` = −128+64+32 = **−32**
- 最大整数：`0110 0000` = 64+32 = **96**
要点：补码当无符号数越大真值越大，所以「让 1 靠后 → 更小」「让 1 靠前 → 更大」。

**例 9（11 题）** 7 位补码（1 符号 + 6 数值），要求真值大于 −32。
解：−32 的补码：−32 = −(2⁵)，原码 `110 0000`，补码 `110 0000`。要比它大，补码必须更大：`X1` 位必须为 1，`X2~X6` 至少一位为 1。答案 C。

**例 10（12 题）** 6 位补码，要求真值小于 −16。
解：−16 = `110 000`（原码补码同形）。更小的数补码更大，但只要 `X1 = 0`（即 `10xxxx`）就落在 −32 ~ −17 区间，必然小于 −16；`X2~X5` 任意。答案 C。

**例 11（课后 32 题）** 给三个 8 位机器数 X、Y、Z，比较大小。
解：无符号：X > Y > Z；有符号补码：Z 为正数最大，X、Y 为负，直接按无符号比得 X > Y。答案 D。
要点：同号直接比、异号看符号；刚学时建议再用「求原码」验一遍。

**例 12（课后 27 题）** `unsigned short x = 65530; unsigned int y = x;` 求 y 的机器数。
解：65530 = 65535 − 5 = 16 个 1 减 5 → `1111 1111 1111 1010` = `FFFA`。零扩展到 32 位：**`0000 FFFA`**。

**例 13（课后 26 题）** 16 位补码 `8FA0` 符号扩展为 32 位。
解：首位 8 ≥ 8 为负，高 16 位补全 1：**`FFFF 8FA0`**（B 选项）。

**例 14（课后 29 题）** `short si = -32767; unsigned short usi = si;` 求 usi。
解：32767 = 2¹⁵−1 = 15 个 1，原码 `1` + 15 个 1；补码 = 符号不变、最右 1 及其右 0 不变、其余取反 → `1000 0000 0000 0001` = `8001`。同字长直接按无符号解释：2¹⁵+1 = **32769**。
另法：−32767 = −32768 + 1，`1000…0` 偏移 1 即得补码。

**例 15（课后 31 题）** `unsigned short usi = 65535; short si = usi;` 求 si。
解：65535 = 16 个 1，按补码解释：全 1 补码 = **−1**。

**例 16（课后 34 题，易错真题）** 16 位有符号 si = −32767，赋给 32 位无符号 ui，求 ui。
解：正确路径是「先符号扩展到 32 位，再按无符号解释」。
si 的补码 `1000 0000 0000 0001` → 符号扩展 `1111 1111 1111 1111 1000 0000 0000 0001` = `FFFF8001`。
按无符号求值：用 2³² 减去缺的部分。`FFFF8001` 比 32 位全 1 少 `0111 1111 1111 1110` = 2¹⁵−2 = 32766，故 ui = (2³²−1) − 32766 = **2³² − 2¹⁵ + 1**。答案 D。
错误做法：先把 si 转成 16 位无符号（`8001`）再零扩展成 `0000 8001` = 2¹⁵+1 = 32769，正好是卷面上的干扰项 B。
